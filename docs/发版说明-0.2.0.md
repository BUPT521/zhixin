# 0.2.0 发版说明

> 0.2.0 于 2026-11-20 发出，是 0.1.x 之后第一份对外安装包，把账号与登录方式拆开、本地数据版本升到 28 这两件事合成一次发出。本版按 [ADR-0017](adr/0017-表结构变化仍清空数据.md) 清空客户端本机库，并按 [ADR-0057](adr/0057-服务端改表清空重建.md) 在当天重建服务端库，没有迁移，也没有兼容分支。安装包由 Actions 构建，74,279,503 字节，放在第一套实例的下载地址 `https://zhixin.chensiyuan.work/downloads/zhixin-0.2.0.apk`，发布清单的 `min_version` 同为 0.2.0；提交与标签是 `v0.2.0`（`8fc1448`），清单里的 SHA-256 与从公网下载回来重算的结果一致。

## 1. 这次清空了哪些数据

| 位置 | 清空的内容 | 保留的内容 |
|---|---|---|
| 客户端 | 0.1.x 的本机库（schema 26），包含学习记录、图片与语义索引；升级后第一次打开时按 schema 28 重建 | 账号、登录状态与服务地址在 Keystore 与 `cloud.json` 里，不在库里，升级之后照常打开；其余设置随库重建为默认值 |
| 服务端 | 2026-11-20 18:16 按 schema 28 重建，账号、会话、验证码、提交序列、备份元数据、附件索引、反馈、活跃数据与按账号的额度覆盖全部清空 | 模型来源、模型、路由与两张实例级的用量表，来源 key 仍用同一个 `ZHIXIN_SECRET_KEY` 解密 |

## 2. 升级之后要做什么

1. 重新注册并登录。服务端的账号已经随库重建清空，旧账号与旧密码都不再存在。
2. 需要留下的学习记录、图片与讨论，请在升级之前用 0.1.x 导出数据包或备份版本库，留作核对；0.1.x 的包不能直接导回 0.2.0，恢复入口只接受当前结构（客户端 schema 28）的包，版本不一致的包在替换之前被拒绝，原数据保留。
3. 把同一账号在其他设备上也升级到 0.2.0。这一版只改变了本地数据版本，账号接口在当天随登录方式拆分一起换了请求体，旧客户端与新服务端互不认识，两端要一起升级。
4. 重新设置学习参数与外观。它们随本机库保存，库重建之后回到默认值。

## 3. 这一版改了什么

- 账号与登录方式分开（[ADR-0038](adr/0038-账号与登录方式分开.md)）：`app_user` 只留密码与创建时间，邮箱移进 `user_identity`，验证码按登录方式保存；接口的请求体从 `email` 改成 `identifier`，验证与确认改成 `POST /v1/me/identities/{id}/verification` 与 `.../confirm`，`GET /v1/me` 返回登录方式列表。
- 数据版本升到 28（[ADR-0039](adr/0039-数据版本的提交类型与同步冲突记录.md)）：本地库按 schema 28 重建，服务端接受的客户端版本跟着改成 28，整库备份、云端同步与数据包都按这一版处理。
- 应用内的更新检查与反馈接口已经接入，下载地址、发布清单与 `sha256` 校验在同一天上线，清单签名由内置的 Ed25519 公钥核对（[ADR-0025](adr/0025-应用内更新检查与反馈的接口口径.md)）。
- 登录、邮箱验证、找回密码、整库备份上传与下载、按提交的增量同步与“知新服务”模型来源在这一版之前已经就位，随包可用；服务端的加固轮次也在同一时期合入，取舍见 [ADR-0028](adr/0028-服务端加固的默认拒绝与预算.md)。

## 4. 这一版还没做的

- 本机数据按账号分空间、记忆的三类表、提交身份只用 `uid`、分表摘要、命名版本随账号同步，都在这一版之后才完成，随 0.3.0 发出（[ADR-0051](adr/0051-记忆改为自由文本条目并走文档检索路径.md)、[ADR-0053](adr/0053-标识按身份顺序指纹分工并收拢提交标识.md)、[ADR-0056](adr/0056-本机数据按账号分空间.md)）。
- 同步的快照压缩、聊天接口统一成 Responses、备份与导入的流式传输在这之后才接入，也随 0.3.0 发出（[ADR-0043](adr/0043-服务端快照登记与提交序列压缩.md)、[ADR-0052](adr/0052-客户端改用OpenAI现行请求格式.md)）。
- 记忆的增改删工具、写入时合并、`search_memory` 与三层召回预算排在 M3，按[长期记忆整理方案](长期记忆整理方案.md#6-实施顺序)的顺序推进。

## 5. 验证与已知问题

客户端的格式检查、`flutter analyze`、全量单元测试，以及服务端的 `gofmt`、`go vet` 与全量测试，在发版提交之前都通过；本包由 CI 构建，安装包哈希与发布清单一致。2026-11-20 的真机验收用的是 0.1.1 的开发包，记录见 [02 第 8.9 节](02-产品与交互.md#89-真机验收记录2026-11-20)，没有覆盖这份安装包的安装与升级路径；V1–V11 的全量模拟器记录在这一版发出时还没有完成，0.3.0 之前补齐。
