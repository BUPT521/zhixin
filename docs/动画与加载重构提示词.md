# 提示词：按《动画流畅性优化方案》重构动效与界面加载

> 用法：在一个新会话里，把下面分隔线之间的内容整段发给助手，并让它能访问 zhixin 仓库根目录。

---

你在知新（zhixin）仓库里工作，这是一个 Flutter 应用，代码在 `app/`，界面层在 `app/lib/ui`。本次任务是**按 `docs/动画流畅性优化方案.md` 重构现有动效与界面加载**：目标是动画不掉帧、内容出现更快、出现时不跳。不新增任何动效种类，也不改视觉设计。

## 开始之前先读

1. `docs/动画流畅性优化方案.md`：全文。第 4 节是动效改动（P0/P1/P2），第 8 节是加载改动（L1–L9），第 5 节是要写回设计系统的规则，第 6 节是取舍。**第 8 节 L3（“先读、后填”）取代第 4 节 P1-1 里“动画结束后再发起读取”的写法**，以 L3 为准。
2. `docs/00-产品定义.md` §5.3 与 `docs/02-产品与交互.md` §2.1 的动效判例；`docs/adr/` 里的约定（开发阶段不向下兼容、本地数据不做迁移）。
3. 涉及的代码：`lib/ui/motion.dart`、`lib/ui/zhixin_segmented.dart`、`lib/ui/home_shell.dart`、`lib/ui/now_page.dart`、`lib/ui/records_page.dart`、`lib/ui/plan_page.dart`、`lib/ui/markdown_text.dart`、`lib/ui/discussion_chat.dart`、`lib/ui/discussion_message.dart`、`lib/ui/learning_page.dart`、`lib/app.dart`、`lib/app_scope.dart`、`lib/main.dart`、`lib/application/context_service.dart`、`test/ui/motion_test.dart`。

方案里的问题判断来自读代码，没有实测。动手前逐条在代码里核实；如果某条与现状不符（已经被改过、或判断有误），跳过它并在最后的汇报里说明，不要硬改。

## 不能动的约束

- 动效口径不变：只说明“内容换了 / 展开了 / 选中项移到了这里”；位移不超过 8px；不缩放、不弹跳、不循环、不做错峰。时长与曲线只从 `ZhixinMotion` 取，不写新数字。
- 系统“减少动态效果”打开时，所有动画（包括新的页面路由过渡）直接到终态。
- 底栏三栏、页签切换后，输入内容、筛选、滚动位置、`MaterialList` 的状态都不能丢。重构包裹结构时，保证当前栏与非当前栏的组件树结构一致。
- 不改数据库表结构与数据包格式；不改 AI 对话协议。
- 代码注释与文档用中文，沿用仓库现有写法：注释说明“为什么”，不复述代码。

## 执行顺序

分批做，每批做完都要跑通检查并单独提交一次，提交信息用中文，说明这一批改了什么、为什么：

1. **第一批（动效 P0）**：方案 P0-1 至 P0-4。`FadeIndexedStack` 改用 `FadeTransition` + `RepaintBoundary` + 非当前栏 `TickerMode(enabled: false)`；`FadeIn`、`ExpandReveal` 同样处理（`ExpandReveal` 可换 `SizeTransition`）；输入区聚焦只变描边颜色，不变宽度；记录页去掉嵌套淡入。在 `motion_test.dart` 补结构断言。
2. **第二批（启动 L1、L2）**：附件清理与图片缓存补建移出首屏路径，放到首帧之后在后台执行，失败照旧写诊断记录；全量补建只在还原、导入或异常退出之后做。用 `deferFirstFrame` / `allowFirstFrame` 让原生启动图直接接上首页，并设约 1.5s 上限；检查深色模式下启动图底色。先确认首屏读取不依赖附件缓存。
3. **第三批（读取与切换 L3、P1-2、P1-3、L4、L5）**：封装一个“过渡结束后再回填”的公共方法，底栏切换与二级页面共用；读取立刻发起，回填等动画结束。`isActive` 与 `dataVersion` 改为页面内部监听，切栏不再重建三栏。页签内容首次进入后常驻。首页互不依赖的查询并行。首读用同高静态骨架代替转圈，已有数据时静默刷新。
4. **第四批（列表、路由与其余）**：P1-4 与 L8 的惰性列表（`ListView.builder` / `SliverList.builder`，替掉 `plan_page` 的 `AnimatedSize`，滚近底部自动加载更多）；P1-5 统一页面路由 `zhixinRoute`（或在 `pageTransitionsTheme` 统一配置），保留系统返回手势；L6 空闲预读；L7 全屏看图限制解码尺寸并用缩略图垫底；L9 讨论页消息先出；P2-2 生成中三点改 `CustomPainter`；P2-3 分段标签字重不再引起抖动。
5. **第五批（流式正文 P2-1）**：先只做“按帧合并分片更新”。分段只重排尾部这一步，只有在合并之后长回答仍明显卡顿时才做，并处理好代码块围栏与列表跨段。
6. **最后**：按方案第 5 节把五条规则写回 `docs/00` §5.3 与 `docs/02` §2.1；在 `docs/动画流畅性优化方案.md` 开头加一段“执行状态”，标明每一项已做、跳过（附原因）还是待实测。如果条件允许，按 P2-4 加 `integration_test` 性能回放用例；没有真机就只写好用例，不编造数据。

## 每批的检查

- 在仓库 `app/` 下 `flutter analyze` 无新增问题，`flutter test` 全部通过；`test/ui/workspace_flow_test.dart` 较慢，可以用 `--total-shards=5 --shard-index=N` 分片跑。
- 每改一个组件，补或更新对应测试，覆盖三件事：动画最后停在终态；减少动态效果时直接到终态；切换前后状态保留。
- 不要为了让测试通过去改测试里的业务断言；测试与新行为冲突时，先确认是测试过时还是改错了。

## 完成后汇报

用简短的中文说明：每一批改了哪些文件和提交号；哪些条目因为与现状不符而跳过、原因是什么；哪些效果需要在真机 profile 模式下验证（列出具体场景与方案第 4、8 节的验收目标）；还有什么遗留风险。在独立分支实现。
