# 知新 · 长期路线图（2026.11–2027.03）

> 本文写清项目在 2026 年 11 月中旬的完成程度、到 2027 年 3 月底之前要做的内容，以及对功能方向的建议。日期、里程碑编号与分工以 [03](03-团队分工与协作.md) 为准，本文只写每个阶段做什么、为什么做、由谁做；产品定义与边界以 [00](00-产品定义.md) 为准，插件的取舍见 [ADR-0010](adr/0010-客户端插件的两种形态与权限.md)。

---

## 1. 现状

2026 年 11 月的可用版已经覆盖产品定义里的主要流程：三栏页面、讨论与作答共用一条学习记录、材料按页导入、系统学习的顺序与继续位置、记忆的提案与纠正、AI 写入的提交与撤销、数据版本、导出与恢复、拍题与语音输入都已实现。客户端约 4.9 万行 Dart 代码，81 个测试文件、约 580 个用例在 CI 上通过。服务端在 `server/` 下有一份 Go 骨架，接口按 OpenAPI 定义，但只有内存存储，客户端还没有接入。

| 部分 | 现状 | 离公测还差的内容 |
|---|---|---|
| 客户端核心流程 | 已实现，三栏页面完成了设计系统精修与动效 | 讨论、学习、材料、记忆、设置五类二级页面的精修，真实数据量下的性能 |
| 验收 | V1–V11 已定义，自动化测试通过；模拟器与真实模型下的验收尚未开始，V10 与 V11 只完成了服务层与记录页 | 在模拟器上走完 V1–V11，相机、语音、安装与性能在 PLK110 上补测 |
| 服务端 | 账号、同步、备份与模型代理的接口已经定义，数据只存在内存里，备份对象接口返回 501 | PostgreSQL 存储、对象存储、部署、日志与备份 |
| 客户端接入 | 未开始 | 登录、整库备份上传与下载、“知新服务”模型来源 |
| 增量同步 | 业务表主键仍是自增整数，设备之间会冲突 | 主键改为全局唯一，再做提交序列的上传与拉取 |
| 提示词 | 规则文本写在 `app/lib/ai/buddy_prompt_builder.dart` 的 Dart 字符串里；长期记忆有一份合成评测用例，真实模型下的对照尚未运行 | 提示词文本独立成文件，建立评测集与打分方式 |
| 插件 | 未开始 | 见第 4 节 |
| 技术债 | drift 只用作执行器；关键词检索按 LIKE 逐条扫描。数据库副本已经统一由 `sqlite3` 打开，sqflite 已从依赖里删除（[ADR-0012](adr/0012-结束sqflite与drift并存.md)） | 真实数据量增长之前改用 FTS5（[ADR-0013](adr/0013-关键词检索改用FTS5.md)），仓库查询迁到生成代码（[ADR-0011](adr/0011-仓库查询改用drift生成代码.md)） |
| 分发与反馈 | 正式包在 Actions 手动构建，应用里没有更新提示，也没有反馈入口 | 更新检查、反馈入口与留存统计 |

结论是功能面已经超出一份演示版的范围，短板集中在三处。第一，产品还没有经过真实用户和真实模型的检验，V1–V11 没有一项在模拟器上正式走过，提示词的质量也没有评测数据支撑。第二，[ADR-0002](adr/0002-本地数据不做迁移.md) 的“升 schema 清空重建”只在内测之前成立，内测用户开始写入真实学习记录之后，任何一次表结构变化都会清空他们的数据，而增量同步需要的主键改造本身就是一次表结构变化。第三，[03 第 4 节](03-团队分工与协作.md#4-成功标准)的 S4 与 S5 要求统计一周与四周留存，目前应用不上报任何使用数据，账号也还没有上线，留存没有数据来源。因此后面的排期先处理这三处，再加新功能。

## 2. 方向建议

建议按公测的需要分成四档。排在前面的项目直接影响公测能否进行或者指标能否测量，排在后面的项目可以增加差异，但不做也不影响结题。

### 2.1 公测前必须完成

| 项目 | 理由 | 主责 |
|---|---|---|
| 账号、整库备份与模型代理 | [ADR-0008](adr/0008-取消单机边界引入账号同步与模型代理.md) 已经采纳；公测的 100 人大多不会自己配置 key，换手机时也不应当丢失记录 | 陈思源 |
| 主键改为全局唯一，并在内测前定下数据保留规则 | 内测之后再改主键会清空内测用户的数据；先改主键，增量同步才能在公测之后接着做 | 吴闻杰（表结构），陈思源（同步需要的约束） |
| 留存统计口径 | S4 与 S5 是结题指标，没有数据来源就无法判定；登录用户可以按服务端请求日期统计活跃天数，不登录的用户需要单独的匿名上报并允许关闭 | 陈思源 |
| 应用内更新检查与反馈入口 | 安装包不走应用商店，100 人分批安装后，旧版本只能靠应用内提示升级；反馈入口附带版本名与可选的诊断记录，缺陷记录才能复现 | 陈思源（接口），吴闻杰（界面） |
| 课表导入 | 安排页的容量计算依赖课表，手工逐节录入是新用户第一次使用时最费时的一步，直接影响 30 秒原则与首日留存 | 陈英硕（插件），吴闻杰（界面） |
| 首次使用引导 | 新用户需要在“登录使用知新服务”和“自填 key”之间选一条路，并导入课表；没有引导时，第一次提问可能直接失败 | 吴闻杰 |
| 提示词评测集 | 公测之后提示词每改一次都会影响所有用户，没有评测集就无法判断改动是变好还是变坏 | 陈英硕（样例与打分），缪鹏（纳入测试） |

### 2.2 建议在公测前完成

| 项目 | 理由 | 主责 |
|---|---|---|
| 人格插件 | 只改提示词里的语气、称呼与讲解风格，不需要新的数据结构，成本低，并且是公测宣传时容易说清楚的差异 | 陈英硕 |
| 分享到知新 | 在 B 站、知乎、浏览器或相册里点“分享”就能把链接、文字或图片带进一次讨论或一份材料；这是与其他应用协作成本最低、也最稳定的方式，不依赖对方的接口 | 吴闻杰（系统入口），陈英硕（内容解析） |
| 二级页面精修 | 讨论、学习、材料、记忆与设置页还沿用精修前的样式，公测用户在这些页面停留的时间不比三栏少 | 吴闻杰 |
| 关键词检索改用 FTS5 | 公测用户的记录量会在几周内超过测试库，LIKE 扫描的耗时随记录数线性增长 | 陈思源 |

### 2.3 有余力再做

| 项目 | 理由 | 代价 |
|---|---|---|
| B 站收藏夹导入 | 把收藏的课程视频变成待学事项，适合用视频自学的用户；只读公开收藏夹或用户分享的链接 | 只能拿到标题、简介与分 P 信息，视频内容与字幕通常需要登录态，接口条款需要核实 |
| 日程导出到系统日历 | 用户可以把已预约的时间块导出成 ICS，由系统日历负责提醒，不违反 [00 第 7 章](00-产品定义.md#7-边界)“本期不做提醒与定时推送”的边界 | 导出之后的修改不会回写知新，需要在界面上说明 |
| 外部调用知新 | 通过深链接与桌面快捷方式，让其他应用或用户直接打开“新建讨论”“当前活动”等入口 | 每开放一个入口都要处理未登录、恢复中与数据代次变化的状态 |
| 增量同步 | 多设备同时使用时不必每次整库恢复 | 冲突规则只定了框架，需要两台设备走查；主键改造必须先完成 |
| 预约提醒 | V8 已经写了试验口径，提醒是留存的常见手段 | 需要修改 00 的边界，并处理通知权限与免打扰；建议看第一轮内测反馈再定 |

### 2.4 本期不建议做

第三方可执行插件、教务系统账号登录抓取、端到端加密、服务端检索、iOS 版本，以及多人共享与班级空间，本期都不建议做。第三方可执行插件需要沙箱与审核机制，团队没有余力维护；教务系统登录需要保存用户的学校账号密码，并且每所学校的页面都不一样，一旦泄露后果比学习记录更严重；端到端加密、服务端检索与多人共享的取舍已经写在 ADR-0008，本文不改变；iOS 需要另外的设备、证书与审核周期，放在结题之后评估。

## 3. 阶段内容

阶段编号与日期见 [03 第 3 节](03-团队分工与协作.md#3-交付节奏)，模块主责见 [03 第 2.1 节](03-团队分工与协作.md#21-模块主责)。下表按阶段列出每个人的主要工作，同一阶段内的顺序就是建议的先后顺序。

### M0 收口与地基

目标是在验收开始之前定下会影响后面所有阶段的几件事：数据保留规则、主键方案、提示词的存放方式与插件的边界，并把在途的改动合进 `main`。

| 成员 | 工作 |
|---|---|
| 陈思源 | 合并在途的语义索引改动；提出同步对主键的要求并评审 D1、D2；服务端接入 PostgreSQL；与陈英硕一起审定 ADR-0010 |
| 吴闻杰 | 接手第 2.1 节划给他的表结构与应用服务模块；写数据保留规则的 ADR（第 5 节 D1），按主键方案完成 schema 提升（D2）；开始二级页面精修，从讨论页与学习页开始 |
| 陈英硕 | 把提示词文本从 Dart 字符串里拆成独立文件，保持行为不变；整理第一版评测集，覆盖 V1、V3、V6 与 V11 中与回答有关的条件 |
| 缪鹏 | 接手 `app/test/` 与 `server/` 的自动化测试，先通读现有用例与 CI 的测试任务；把 V1–V11 拆成可以逐步执行的用例与测试数据；确定缺陷登记方式（建议用仓库的 Issues，标题写版本名与 V 编号） |

完成标准是 `main` 上没有在途分支，数据保留规则与主键方案已经写成 ADR 并实现，提示词改动不需要修改 Dart 逻辑代码。

### M1 验收与内测包

目标是发出 0.2.0 内测包，并且这一版的表结构就是公测要用的表结构。

| 成员 | 工作 |
|---|---|
| 陈思源 | 服务端完成整库备份（对象存储）与模型代理，部署到测试服务器；更新检查与反馈接口；关键词检索改用 FTS5；发版 0.2.0 |
| 吴闻杰 | 修验收发现的界面与服务层缺陷；完成二级页面精修；反馈入口与更新提示的界面；FTS5 需要的表结构 |
| 陈英硕 | 按评测集调优讨论、提示与检查三类回答；实现插件运行时的第一版与人格插件，先在开发包里开放 |
| 缪鹏 | 为主键改造与 FTS5 补自动化测试；在模拟器上执行 V1–V11 并记录结果；真实模型下抽检回答；准备内测说明与第一批内测名单 |

完成标准是 V1–V11 在模拟器上全部有记录，阻断级缺陷清零，0.2.0 已经发到第一批内测用户。

### M2 第一轮内测与期末

第一轮内测持续两周，之后进入期末，团队只修阻断级缺陷，必要时发 0.2.x 修订版。缪鹏负责收集与整理反馈，陈英硕从反馈里挑出回答质量相关的样例补进评测集，其余成员按课业安排降低投入。陈思源在这一阶段只做服务端上线前的安全检查，包括 TLS、数据库与对象存储的加密、访问日志不记正文、删除云端数据的接口，不开新功能。

### M3 账号、备份与第一批插件

寒假的前三周是整个计划里开发量最大的一段，目标是发出 0.3.0 并把内测扩到 30 人。

| 成员 | 工作 |
|---|---|
| 陈思源 | 客户端登录、整库备份上传与下载、“知新服务”模型来源的接入，与吴闻杰一起联调；留存统计（D3）；如果时间允许，开始增量同步的服务端部分 |
| 吴闻杰 | 登录、云备份与模型来源的设置界面；首次使用引导；分享到知新的系统入口；插件管理页 |
| 陈英硕 | 课表导入插件（截图识别、ICS 文件与模板表格三种来源）；人格插件开放给内测用户，提供三到五个预置人格；分享内容的解析 |
| 缪鹏 | 回归 V1–V11；为账号、备份恢复、服务端接口与插件编写自动化测试与验收用例；执行第二轮内测 |

完成标准是一个新用户可以在不配置 key 的情况下登录、导入课表、完成一次讨论，并且换一台模拟器登录后能恢复全部记录。

### M4 春节与公测准备

春节一周不排开发，只收集第二轮内测的反馈。春节之后两周修缺陷，并按进度从第 2.3 节里选做 B 站收藏夹导入或日程导出；功能冻结之后只修缺陷，冻结日期见 03。陈思源在冻结前完成正式服务器的部署与备份演练，缪鹏完成公测说明、隐私说明与公测名单。

### M5 公测与结题

1.0.0 公测从 3 月第一天开始，需要满四周才能计算四周留存，所以公测的开始日期不能晚于 03 规定的日期。公测期间按反馈完成一次版本迭代，3 月下半月整理研究报告、软著申请与答辩材料：数字与样本边界由缪鹏核对，答辩用的界面截图与录屏由吴闻杰准备，提示词与插件的评测结果由陈英硕整理，技术架构与服务端运行数据由陈思源整理。

## 4. 插件路线

插件分为两类，形态、权限与写入规则见 [ADR-0010](adr/0010-客户端插件的两种形态与权限.md)，本节只写交付顺序。

能力插件让知新与其他应用或网站协作，既可以把外部的数据带进来，例如导入课表或读取 B 站收藏夹，也可以让外部调用知新的部分功能。能力插件随应用一起编译，代码放在 `app/lib/plugins/` 下，每个插件声明自己需要的权限，写入的数据都经过应用服务形成一条可撤销的提交。人格插件是一份文本配置，只改变搭子的语气、称呼、讲解风格与篇幅倾向，不能改变判分、引用、写入权限与工具规则，用户可以导入、分享与删除。

| 批次 | 插件 | 阶段 |
|---|---|---|
| 第一批 | 插件运行时、人格插件、课表导入、分享到知新 | M1 起做运行时，M3 对内测用户开放 |
| 第二批 | B 站收藏夹导入、日程导出到系统日历、深链接入口 | M4，按进度选做 |
| 结题之后 | 第三方插件、远程工具服务（例如 MCP）、教务系统适配 | 公测数据出来之后再评估 |

陈英硕负责插件运行时与插件本身，可以修改 `app/lib/plugins/`、`app/lib/ai/` 下的提示词与工具说明以及对应的评测；插件需要新的表、字段或数据包格式时，先由吴闻杰改 01 与表结构，数据包格式由陈思源改，插件不直接访问数据库。每个插件合入之前由陈思源审一遍权限声明与写入路径，由缪鹏按插件用例验收；人格插件在合入或预置之前要通过评测集里与判分、引用和编造有关的用例。

## 5. 待定决定

下表是排期依赖的决定，没有定下来之前，相关阶段只能按建议执行。

| 编号 | 问题 | 建议 | 负责人 | 最晚 |
|---|---|---|---|---|
| D1 | 内测开始之后，表结构变化是否仍然清空数据 | 继续不写迁移，但把已知的结构改动（主键改造）全部放在 0.2.0 之前完成，内测与公测期间冻结表结构，只有阻断级缺陷才允许提升，并提前告知内测用户会清空；1.0.0 之后是否写迁移另行决定。结论写一条 ADR，补充 ADR-0002 在内测之后的适用范围 | 吴闻杰 | M0 结束 |
| D2 | 业务表主键的全局唯一方案 | UUIDv7 文本主键，在 0.2.0 之前完成这次 schema 提升 | 吴闻杰（陈思源评审） | M0 结束 |
| D3 | 留存怎样统计 | 登录用户按服务端请求的日期计活跃天数；不登录的用户每天上报一次随机安装标识与日期，不含任何学习内容，首次使用时说明并允许关闭，设置页也可以关闭；默认开启还是默认关闭待定，结论写进 ADR-0008 的隐私边界 | 陈思源 | M2 结束 |
| D4 | 模型代理的每日额度与经费来源 | 按内测期间的实际用量定，先用配置项控制 | 陈思源 | M3 开始前 |
| D5 | 人格设定与记忆中的讲解偏好冲突时以谁为准 | 用户本轮说明最优先，其次是当前启用的人格，再次是记忆里的风格偏好；记忆中的困难与时间限制不受人格影响。由评测结果确认 | 陈英硕 | M3 开始前 |
| D6 | 公测是否加入预约提醒或日程导出 | 看第一轮内测反馈，倾向先做日程导出 | 全员 | M4 开始前 |
| D7 | 服务器的第二位管理员 | 陈思源之外再指定一人，保管恢复用的凭据，防止单人不可用时无法处理事故 | 陈思源 | M3 开始前 |

## 6. 进度落后时的取舍

按 [03 第 1 节](03-团队分工与协作.md#1-协作原则)的原则，进度落后时砍范围而不加时间。新增的内容按以下顺序先砍：第 2.3 节的全部项目，其次是增量同步，然后是人格插件的预置数量与分享到知新，再然后是二级页面精修中设置与记忆两页。账号、整库备份、模型代理、课表导入、留存统计与更新检查不砍，因为缺少其中任何一项，公测都难以按 S5 的要求进行。如果这几项也无法按期完成，只剩两种做法：公测推迟，四周观察期随之延到 4 月，与 3 月底截止的安排冲突；或者按期公测，缺少的项目在公测期间补上，留存数据的口径在结题材料里说明。两种做法的代价不同，到 M4 开始时由全员决定，不在本文预先选定。
