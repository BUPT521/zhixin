# 知新 · 长期路线图（2026.11–2027.03）

> 本文写清项目在 2026 年 11 月中旬的完成程度、到 2027 年 3 月底之前要做的内容，以及对功能方向的建议。日期、里程碑编号与分工以 [03](03-团队分工与协作.md) 为准，本文只写每个阶段做什么、为什么做、由谁做；产品定义与边界以 [00](00-产品定义.md) 为准，插件的取舍见 [ADR-0010](adr/0010-客户端插件的两种形态与权限.md)。

## 1. 现状

2026 年 11 月的可用版已经覆盖产品定义里的主要流程：三栏页面、讨论与作答共用一条学习记录、材料按页导入、系统学习的顺序与继续位置、记忆的提案与纠正、AI 写入的提交与撤销、数据版本、导出与恢复、拍题与语音输入都已实现。客户端 `lib/` 约 6.2 万行手写 Dart 代码，`test/` 下 147 个文件、914 个用例在 CI 上运行，其中 24 个依赖 zvec 原生库的用例在未配置时跳过。服务端在 `server/` 下有一份 Go 服务，接口按 OpenAPI 定义，PostgreSQL 存储与对象存储已经接上，附件接口按契约实现，客户端已经接入登录、邮箱验证、找回密码、备份、增量同步与模型代理。

| 部分 | 现状 | 离公测还差的内容 |
|---|---|---|
| 客户端核心流程 | 已实现，三栏页面与讨论、学习、材料、记忆、设置等二级页面完成了设计系统精修，P2 项与深色、大字号下的截图复核待补 | 真实数据量下的性能 |

| 增量同步 | 业务表主键已按 [ADR-0018](adr/0018-业务表主键改用UUIDv7.md) 改为 UUIDv7 文本（schema 27），客户端已经按提交序列上传与拉取，附件按哈希补齐 | 两台设备的同步走查与冲突规则复核 |

| 技术债 | 仓库读写改用 drift 生成的类型化语句（[ADR-0011](adr/0011-仓库查询改用drift生成代码.md)），关键词与语义检索并入 zvec（[ADR-0024](adr/0024-关键词检索并入zvec.md)），记忆召回的排序改由同一引擎的全文索引给出（[ADR-0026](adr/0026-记忆召回改用zvec全文索引.md)），数据库副本统一由 `sqlite3` 打开、sqflite 已从依赖里删除（[ADR-0012](adr/0012-结束sqflite与drift并存.md)）；页面改为订阅跟随写入更新的整屏读法，写入、撤销、导入与换库之后不再手动重读（[ADR-0014](adr/0014-流式查询与版本通知.md)） | 真实数据量下的长列表分页与订阅开销复核 |
| 分发与反馈 | 正式包在 Actions 手动构建，服务端已提供更新检查与反馈接口（2026-11-18），应用内的启动更新提示、设置页“检查更新”与反馈入口同日接入；留存统计的服务端接收、按日统计与保留期清理，以及客户端的匿名上报、首次说明与设置开关同日完成 | 发版人填好签名公钥之后按 A7 验收，以及内测用户实际提交反馈 |

结论是功能面已经超出一份演示版的范围，短板集中在三处。第一，产品还没有经过真实用户和真实模型的检验，V1–V11 只有 V1 与 V10 的部分条件在模拟器上验证过（[02 第 8.5 节](02-产品与交互.md#85-模拟器冒烟记录)），提示词的质量也没有评测数据支撑。第二，[ADR-0002](adr/0002-本地数据不做迁移.md) 的清空规则已经延伸到内测与公测（[ADR-0017](adr/0017-表结构变化仍清空数据.md)），内测用户开始写入真实记录之后，任何一次表结构变化仍会清空数据，主键改造本身就是一次表结构变化；这条代价已经接受，靠发版说明与应用内提示交代清楚。第三，[03 第 4 节](03-团队分工与协作.md#4-成功标准)的 S4 与 S5 要求统计一周与四周留存，账号与匿名的活跃上报已于 2026-11-17、2026-11-18 接入（[ADR-0019](adr/0019-留存统计用匿名上报.md)），数据来源已经具备，真实用户的留存要等第一轮内测开始才有数字。因此后面的排期先处理这三处，再加新功能。

## 2. 方向建议

建议按公测的需要分成四档。排在前面的项目直接影响公测能否进行或者指标能否测量，排在后面的项目可以增加差异，但不做也不影响结题。

### 2.1 公测前必须完成

| 项目 | 理由 | 主责 |
|---|---|---|
| 账号、整库备份与模型代理 | [ADR-0008](adr/0008-取消单机边界引入账号同步与模型代理.md) 已经采纳；公测的 100 人大多不会自己配置 key，换手机时也不应当丢失记录 | 陈思源 |
| 主键改用 UUIDv7 | 增量同步的前提，见 [ADR-0018](adr/0018-业务表主键改用UUIDv7.md)；2026-11-16 完成，13 张业务表的主键改为文本、schema 升到 27，旧库按 [ADR-0017](adr/0017-表结构变化仍清空数据.md) 清空 | 吴闻杰（表结构），陈思源（同步需要的约束） |
| 留存统计的匿名上报 | S4 与 S5 是结题指标，没有数据来源就无法判定；登录用户按服务端请求日期统计活跃，不登录的用户匿名上报并允许关闭，见 [ADR-0019](adr/0019-留存统计用匿名上报.md) | 陈思源 |
| 预约提醒与日程导出 | 提醒直接影响留存，导出把已预约的时间交给系统日历；两项已定要做，不等内测反馈，形态见 [ADR-0020](adr/0020-预约提醒用本地通知与日程导出用ICS.md) | 吴闻杰（界面与通知），陈思源（导出格式与权限口径） |
| 应用内更新检查与反馈入口 | 安装包不走应用商店，100 人分批安装后，旧版本只能靠应用内提示升级；反馈入口附带版本名与可选的诊断记录，缺陷记录才能复现 | 陈思源（接口），吴闻杰（界面）；2026-11-18 已完成 |
| 课表导入 | 安排页的容量计算依赖课表，手工逐节录入是新用户第一次使用时最费时的一步，直接影响 30 秒原则与首日留存 | 陈英硕（插件），吴闻杰（界面） |
| 首次使用引导 | 新用户需要在“登录使用知新服务”和“自填 key”之间选一条路，并导入课表；没有引导时，第一次提问可能直接失败 | 吴闻杰 |
| 提示词评测集 | 公测之后提示词每改一次都会影响所有用户，没有评测集就无法判断改动是变好还是变坏 | 陈英硕（样例与打分），缪鹏（纳入测试） |
| 记录页其余四个查找入口 | V10 要求每个入口都能翻到最早一条，当前只有记录页搜索与“加入本次回答”可用，缺的入口不补齐，V10 无法通过 | 吴闻杰；2026-11-18 已完成，待 V10 验收 |
| 邮箱验证与找回密码 | 100 人公测里一定有人忘记密码；没有找回途径，账号里的云备份就取不回来，邮箱验证同时保证找回邮件发得到本人 | 陈思源（服务端与发信），吴闻杰（界面）；2026-11-17 已完成 |

### 2.2 建议在公测前完成

| 项目 | 理由 | 主责 |
|---|---|---|
| 人格插件 | 只改提示词里的语气、称呼与讲解风格，不需要新的数据结构，成本低，并且是公测宣传时容易说清楚的差异 | 陈英硕 |
| 分享到知新 | 在 B 站、知乎、浏览器或相册里点“分享”就能把链接、文字或图片带进一次讨论或一份材料；这是与其他应用协作成本最低、也最稳定的方式，不依赖对方的接口 | 吴闻杰（系统入口），陈英硕（内容解析） |

### 2.3 有余力再做

| 项目 | 理由 | 代价 |
|---|---|---|
| B 站收藏夹导入 | 把收藏的课程视频变成待学事项，适合用视频自学的用户；只读公开收藏夹或用户分享的链接 | 只能拿到标题、简介与分 P 信息，视频内容与字幕通常需要登录态，接口条款需要核实 |
| 外部调用知新 | 通过深链接与桌面快捷方式，让其他应用或用户直接打开“新建讨论”“当前活动”等入口 | 每开放一个入口都要处理未登录、恢复中与数据代次变化的状态 |
| 增量同步 | 多设备同时使用时不必每次整库恢复 | 冲突规则只定了框架，需要两台设备走查；业务表主键已按 [ADR-0018](adr/0018-业务表主键改用UUIDv7.md) 改为 UUIDv7 文本 |

### 2.4 本期不建议做

第三方可执行插件、教务系统账号登录抓取、端到端加密、iOS 版本，以及多人共享与班级空间，本期都不建议做。第三方可执行插件需要沙箱与审核机制，团队没有余力维护；教务系统登录需要保存用户的学校账号密码，并且每所学校的页面都不一样，一旦泄露后果比学习记录更严重；端到端加密与多人共享的取舍已经写在 ADR-0008，服务端承担嵌入、检索索引留在本机（[ADR-0030](adr/0030-服务端不建检索索引.md)），排期另定；iOS 需要另外的设备、证书与审核周期，放在结题之后评估。

## 4. 插件路线

插件分为两类，形态、权限与写入规则见 [ADR-0010](adr/0010-客户端插件的两种形态与权限.md)，ADR-0010 已于 2026-11-16 定稿，本节只写交付顺序。

能力插件让知新与其他应用或网站协作，既可以将外部的数据带进来，例如导入课表或读取 B 站收藏夹，也可以让外部调用知新的部分功能。能力插件随应用一起编译，代码放在 `app/lib/plugins/` 下，每个插件声明自己需要的权限，写入的数据都经过应用服务形成一条可撤销的提交。人格插件是一份文本配置，挂在同一个插件运行时上，与能力插件共用设置页启停；它只改变搭子的语气、称呼、讲解风格与篇幅倾向，不能改变判分、引用、写入权限与工具规则，用户可以导入、分享与删除，导入与分享都使用纯文本。

| 批次 | 插件 | 阶段 |
|---|---|---|
| 第一批 | 插件运行时、人格插件、课表导入、分享到知新 | M1 起做运行时，M3 对内测用户开放 |
| 第二批 | B 站收藏夹导入、日程导出到系统日历、深链接入口 | M4，按进度选做 |
| 结题之后 | 第三方插件、远程工具服务（例如 MCP）、教务系统适配 | 公测数据出来之后再评估 |

陈英硕负责插件运行时与插件本身，可以修改 `app/lib/plugins/`、`app/lib/ai/` 下的提示词与工具说明以及对应的评测；插件需要新的表、字段或数据包格式时，先由吴闻杰改 01 与表结构，数据包格式由陈思源改，插件不直接访问数据库。每个插件合入之前由陈思源审一遍权限声明与写入路径，由缪鹏按插件用例验收；人格插件在合入或预置之前要通过评测集里与判分、引用和编造有关的用例。

## 6. 进度落后时的取舍

按 [03 第 1 节](03-团队分工与协作.md#1-协作原则)的原则，进度落后时砍范围而不加时间。新增的内容按以下顺序先砍：第 2.3 节的全部项目，其次是增量同步，然后是人格插件的预置数量与分享到知新。账号、整库备份、模型代理、主键改造、留存统计、预约提醒与日程导出、课表导入与更新检查不砍，因为缺少其中任何一项，公测都难以按 S5 的要求进行。如果这几项也无法按期完成，只剩两种做法：公测推迟，四周观察期随之延到 4 月，与 3 月底截止的安排冲突；或者按期公测，缺少的项目在公测期间补上，留存数据的口径在结题材料里说明。两种做法的代价不同，到 M4 开始时由全员决定，不在本文预先选定。
