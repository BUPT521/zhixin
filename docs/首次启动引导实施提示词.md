# 首次启动引导实施提示词

下面整段交给实施的人（或模型）。写于 2026-11-26，按当时 main 的代码写成，开工前先核对文中提到的文件与行为是否已变。

## 任务

为知新客户端（`app/`，Flutter）实现首次启动引导。引导按顺序三步：同意用户须知与隐私政策、登录或注册（可跳过）、选择主题色与深浅色。完成之后进入现有的 `HomeShell`，之后的启动不再出现。

## 先读

- `docs/02-产品与交互.md` 第 3.1 节（首次使用）、第 3.12 节（外观）、第 3.16 节（账号与云同步）。
- `docs/用户须知与隐私政策草稿.md`，尤其“定稿前要核实的事”。
- ADR-0019（匿名上报）、ADR-0050（客户端统一为知新服务，不登录不能用模型）、ADR-0056（本机数据按账号分空间）。
- 代码：`app/lib/main.dart`、`app/lib/app.dart`、`app/lib/app_scope.dart`（约 1025 行的 `reportIfDue`）、`app/lib/ui/home_shell.dart`（`_runStartupChecks`）、`app/lib/ui/telemetry_notice.dart`、`app/lib/ui/update_notice.dart`、`app/lib/ui/account_page.dart`（`_submit` 与登录卡）、`app/lib/ui/theme.dart`（`ZhixinAccent`）、`app/lib/ui/theme_accent_controller.dart`、`app/lib/ui/theme_mode_controller.dart`、`app/lib/platform/diagnostics_store.dart`。

## 已定的做法

1. 引导在同意之前不发出任何网络请求。现在启动时会做的匿名上报（`AppScope` 里的 `reportIfDue`）与更新检查（`HomeShell._runStartupChecks`）都要等引导完成、并且用户同意之后才执行。
2. 第一步“须知与隐私”：一页，列出《用户须知》《隐私政策》两个入口（先打开应用内页面，正文可以暂用草稿全文），一个不预先勾选的“我已阅读并同意”，按钮“同意并继续”在勾选前不可点。同一页放“匿名使用统计”开关，默认开启，说明文字沿用 `telemetry_notice.dart` 的内容；这一页完成时调用 `ActiveReportService.completeNotice(enabled: ...)`，此后 `showTelemetryNoticeIfNeeded` 不会再弹。提供“不同意”：不退出应用，进入纯本机模式，不上报、不检查更新、不显示登录步骤，直接跳到第三步；设置页“诊断与隐私”里加一个“查看并同意用户须知”入口，同意之后恢复联网功能。
3. 记下同意的须知版本。在代码里定义一个常量（例如 `kTermsVersion = 1`），同意时写入；启动时存下的版本小于常量就只重新显示第一步。
4. 第二步“登录”：把 `account_page.dart` 里的登录与注册表单抽成独立组件，账号页与引导共用，不复制代码；`_submit` 里的校验（邮箱与密码非空、密码至少 8 位）、错误提示与登录后 `sync.schedule` 一起搬过去。引导里不出现服务地址，登录只连出厂默认实例；换实例的入口留在设置页的开发者模式，账号页只显示当前地址（[ADR-0064](adr/0064-客户端开发者模式.md)）。不在引导里要求邮箱验证与找回密码以外的流程，找回密码给一个跳到账号页的链接即可。跳过按钮写“先在本机用”，旁边一句说明不登录不能用模型提示、讲解与云同步（与 ADR-0050 一致）。全新安装时本机库为空，登录后不要在引导中途弹出“首次上传本机记录”的确认。
5. 第三步“外观”：六个主题色色块（取 `ZhixinAccent.values`，默认蓝色选中）与“跟随系统 / 浅色 / 深色”三选一，点选直接调用两个控制器的 `select`，整页即时换色，不另做预览图。“跳过”保留默认值。应用图标不随主题色变化，这一页不提图标。
6. 完成标记与已同意的须知版本存在设备级位置：根 `filesDir` 下的小文件，写法照 `DiagnosticsStore`（`AtomicFile` 原子写）。不能存在空间目录里：按 ADR-0056，退出登录会新建一个空的未登录空间，按空间存会让引导重复出现。新建 `app/lib/platform/onboarding_store.dart`，读写“完成标记”“须知版本”“是否同意”三项，读失败按未完成处理。
7. 入口在 `app.dart`：`home` 根据引导状态在引导页与 `HomeShell` 之间二选一，不要把引导作为 `HomeShell` 之上的路由推出，否则 `HomeShell` 的启动检查会在同意之前跑。引导不需要读库，可以尽早放行 `FirstFrameGate`。
8. 登录会触发换空间：`ZhixinApp._changeSpace` 换掉 `AppScope` 的 `GlobalKey`，整棵子树重建，主题控制器也从新空间重新读取。引导当前在第几步不能只放在引导页的 `State` 里，要么提到 `AppScope` 之外，要么每一步完成就写进 `OnboardingStore`，重建之后从记下的步骤继续。第一次登录时未登录空间会改为账号空间，此前选的外观随之保留；验证这一点。
9. 老用户升级：没有完成标记，但已经登录、本机库非空或已经看过匿名统计说明的，视为老用户，只显示第一步，同意后直接进入 `HomeShell`。
10. 返回键：第二、三步返回上一步；第一步返回退出应用。页面过渡沿用主题里按平台配置的路由过渡，不自己写动画。
11. 课表导入不放进引导。
