# 0.3.0 发版说明

> 0.3.0 于 2026-11-24 发出，是首轮内测包，把 0.2.0 之后的表结构变化、同步与模型链路的改动合成一次发出。本版按 [ADR-0017](adr/0017-表结构变化仍清空数据.md) 清空客户端各空间的本机库，服务端在发出之前按 [ADR-0057](adr/0057-服务端改表清空重建.md) 整份重建，没有迁移，也没有兼容分支。安装包由 Actions 在 `0ec4aa6` 上构建，arm64 单包 74,529,199 字节，SHA-256 为 `8910290818259e607627b3297ad60b88f31cf4d65efc57c07deb6c2c048fe01f`，同时放在 GitHub Release（标签 `v0.3.0`，附同名的 `.sha256` 与 `.sig`）与下载地址 `https://zhixin.chensiyuan.work/downloads/zhixin-0.3.0.apk`，发布清单的 `min_version` 同为 0.3.0，从公网下载回来重算的哈希与清单一致。发版时间比 [03 第 3 节](03-团队分工与协作.md#3-交付节奏)排的 12 月 21 日提前，因为 11 月 23 日服务端按 schema 32 重建之后，公网上的 0.2.0 已经不能同步，聊天接口也换成 Responses 格式，旧包等不到排期。

## 1. 这次清空了哪些数据

| 位置 | 清空的内容 | 保留的内容 |
|---|---|---|
| 客户端 | schema 28 与 schema 31 的本机数据，包含学习记录、图片、语义索引、恢复点与设置；schema 31 的空间库在升级后第一次打开时按 schema 32 清空重建，0.2.0 的 `filesDir/zhixin.db`、`question_images/`、`vector_index/`、`memory_index/`、`restore_points/` 与 `data_versions/` 这套单体布局在第一次启动时删除 | 账号、登录状态与服务地址在 Keystore 与 `cloud.json` 里，不在库里；设备标识保留 |
| 服务端 | 按 schema 32 整份重建（[ADR-0057](adr/0057-服务端改表清空重建.md)），账号、会话、验证码、提交序列、快照、设备名册、命名版本、备份元数据、附件索引与按账号的额度覆盖全部清空，对象存储 `attachments/` 前缀下的字节同时清空 | 模型来源、模型、路由与两张实例级的用量表，来源 key 仍用同一个 `ZHIXIN_SECRET_KEY` 解密 |

客户端这次按 [ADR-0017](adr/0017-表结构变化仍清空数据.md) 处理，服务端按 [ADR-0057](adr/0057-服务端改表清空重建.md) 处理，两端都不写迁移：本机空间库只要不是 schema 32 就在打开时清空重建，0.2.0 的单体布局不打开，旧目录在第一次启动时删除；两类数据包与版本库备份只接受 schema 32，低于或高于 32 的包在替换之前被拒绝、原数据保留。

## 2. 升级之后要做什么

1. 重新注册并登录。服务端的账号已经随重建清空，旧账号、旧密码与旧令牌都不再存在。
2. 需要留下的学习记录、图片与讨论，请在升级之前导出版本库备份或数据包，留作核对；schema 28 与 schema 31 的包都不能导回 0.3.0，恢复入口只接受 schema 32 的包与版本库备份，版本不一致的包在替换之前被拒绝，原数据保留。升级之后本机库在第一次打开时清空重建，0.2.0 的旧目录同时删除；升级之前没有导出的本机记录无法找回。
3. 把同一账号在其他设备上也升级到 0.3.0。同步契约把提交类型 `kind` 改为必填字段，服务端拒绝缺字段与未知取值，并且只接受 schema 32 的客户端；旧客户端与新服务端互不认识，两端要一起升级，服务端用 `/readyz` 报告的 schema 版本判断，版本不一致时直接说明两端要一起升级。
4. 重新导入材料与课表，并重填本机设置。它们随账号空间保存，空间重建之后回到默认值；外观、每日截止小时与插件启停这些设置也要重新设置一遍。

## 3. 这一版改了什么

- 本机库与同步契约按 schema 32 收口：记忆的召回与主动搜索先记在不参与采集的本机缓冲表 `local_memory_use`，冲刷时在一条 `maintenance` 提交里汇总进按记忆与设备一行的 `memory_usage`；讨论是否结束由 `ended_at` 推出；提交类型去掉 `remote`，来源只看设备标识，同步载荷的提交对象必填 `kind`；附件引用改为在表结构里声明，消息的图片列改名为 `image_hashes_json`；远端提交的列组整组写入，撞上非主键唯一约束时按声明把本机行改号或者跳过远端这一行并记冲突（[审查 S16 至 S23](数据库结构过度设计审查.md#9-schema-32-复审)）。
- 服务端删去 `user_purge`，清除期间的互斥只在进程内；`sync_commit` 增加必填 `kind`，删去 `UNIQUE (user_id, uid)` 与 `sync_ref_by_user`、`embedding_cache_by_model`、`attachment_user_created` 三条索引，去重只查 `sync_commit_seen`；附件回填命令与相关查询一并删除（[审查 V5、V6、V10、V16 至 V18](数据库结构过度设计审查.md#9-schema-32-复审)）。
- 本地库按账号分空间：一个账号一个空间，切换账号不再把上一份记录带过去，也不反复整份上传；0.2.0 的单体布局在第一次启动时删除。退出登录可以保留或删除这个账号在设备上的数据，“清除云端数据”改名为“清除全部数据”，“清理历史”改名为“清理本机历史”（[ADR-0056](adr/0056-本机数据按账号分空间.md)）。
- 命名版本随账号同步，换设备之后能看到名字；名字指向的提交已经不在本机时注明该版本的历史不在本机，需要长期保留时请导出版本库备份，[ADR-0054](adr/0054-数据版本位置标记补强.md) 把这种只剩名字的版本称为“只剩标签”。
- 一致性摘要按表拆开比较，不一致时账号页写明哪几张表不同，并给出“以本机为准重建云端”一个入口（[ADR-0045](adr/0045-同步两端的一致性摘要.md)、[ADR-0054](adr/0054-数据版本位置标记补强.md)）。
- 数据完整性检查改为从最近的检查点重放到 `HEAD` 比对摘要，不再维护提交哈希链（[数据库结构过度设计审查](数据库结构过度设计审查.md) S1、S10）。
- 记忆改为自由文本条目，按情景、语义、程序三类组织，删除改为改状态；写入查重、主动搜索与“很久没用到”的整理建议要用的字段与使用统计已经建好（[ADR-0051](adr/0051-记忆改为自由文本条目并走文档检索路径.md)）。
- 同步接入快照压缩：服务端声明压缩开启时客户端上传整库快照，服务端历史被压缩之后，首次同步与遇到 410 的设备按快照重建，这两情形在 ADR 里分别叫浅克隆与重新克隆，界面上统一叫“按快照重建”（[ADR-0043](adr/0043-服务端快照登记与提交序列压缩.md)、[ADR-0046](adr/0046-客户端按快照浅克隆与重新克隆.md)、[ADR-0047](adr/0047-快照附件回收与压缩前的客户端门槛.md)）。内测实例已于 2026-11-23 打开 `ZHIXIN_SYNC_COMPACT`（`KEEP=720h`）。
- 聊天接口统一成 OpenAI 现行的 Responses 格式，客户端不再发送 Chat Completions 的字段，模型名与上下文上限在设置页填写、由服务端按后台目录校验并补默认值（[ADR-0052](adr/0052-客户端改用OpenAI现行请求格式.md)、[ADR-0055](adr/0055-模型调用协议与上限统一.md)）。服务端部署之后，仍在用 0.2.0 的客户端聊天会失败，需要一起升级。
- 云端备份的上传与下载改为流式，导入包增加条目数与解压总量预算（[技术审查清单](项目技术审查与整改清单.md)的 DATA-01、DATA-02）；检查更新不再预先下载安装包，用户确认后由系统浏览器下载一次（UPDATE-01）。
- 嵌入来源只剩知新服务与本机哈希两项，查询向量也走云端（[ADR-0049](adr/0049-嵌入统一走百炼与查询向量也走云端.md)、[ADR-0050](adr/0050-客户端统一为知新服务.md)）。

## 4. 这一版还没做的

- 记忆的增改删三个工具、写入时合并近似条目、`search_memory`、三层召回预算与“很久没用到”的整理建议排在 M3，按[长期记忆整理方案](长期记忆整理方案.md#6-实施顺序)的顺序推进；这一版先把表建好，写入仍限 200 字。
- 预约提醒与日程导出按 [ADR-0020](adr/0020-预约提醒用本地通知与日程导出用ICS.md) 排在后面，本版表结构不为它们预留列。
- 首次使用引导、课表导入、分享到知新与人格插件对内测用户开放排在 M3，本版不包含。
- 记忆的语义检索按 ADR-0051 决定第 10 条沿用全文检索；查询向量虽已走云端，记忆条目本身不嵌入。

## 5. 验证与已知问题

客户端的格式检查、`flutter analyze`、全量单元测试（本机 1200 多个用例），服务端的 `gofmt`、`go vet` 与全量测试在推送之前都通过；两台独立客户端实例在 2026-11-23 走查了基线上传、快照登记、压缩、410 重建与双向同步，全部通过。schema 32 之后按同一套同步顺序在两端又走查了一次。服务端的全量测试通过：`TestTwoDeviceSyncWalkthrough` 按基线、交替推送、409 重推、同一 `uid` 重试、附件与清空后重建九步走完；`TestHandlerCommitKindIsRequiredAndRoundTripped` 核对缺 `kind` 与三个未知取值（`remote`、`checkpoint`、空串）都返回 400 `invalid_request`，被拒绝的提交不写入，带 `kind` 的提交在拉取时原样带回；另在内存实例上提交了课表起止时间整组变更、`plan_item` 改号后的更新与材料页插入，三条提交都原样保存、原样拉回。列组整组写入与两种唯一键处置由客户端的应用规则实现，`revision_constraint_conflict_test.dart` 逐条走查整组写入、`plan_item` 改号保留两行、`material_page` 跳过并记 `unique_key_taken`、`memory_usage` 跳过并记冲突；`sync_service_test.dart` 与 `sync_snapshot_test.dart` 覆盖基线、压缩、410 重建与双向同步。这次重跑全量 1258 个用例通过；首次与并行构建同时运行时 `workspace_data_test.dart` 有一个用例超过十分钟超时，空载重跑该文件与全量都通过，判断为当时负载造成的超时。升级走查在 Android 15（API 35）模拟器上完成：先装 v0.2.0 标签的调试包（版本名 0.2.0-dev、构建号 3、schema 28），注册并同步一次，再覆盖安装 main 的 0.3.0 调试包（0.3.0-dev、构建号 4、schema 32）。0.2.0 启动后留下 `zhixin.db` 与 `question_images/`，升级前又按它的目录形状补了 `vector_index/`、`memory_index/`、`restore_points/`、`data_versions/`、`cloud_backup_*`、`cloud_download_*`、`.restore-*` 与 `attachment_cache.pending`；升级后这些条目连同 `zhixin.db-shm`、`zhixin.db-wal` 全部删除，`cloud.json`、`telemetry.json`、`diagnostics.json` 与 `profileInstalled` 保留，其中 `cloud.json` 与升级前逐字节相同。Keystore 里的会话、资料与设备标识三个键也在升级前后逐字节相同，0.3.0 打开后账号页仍显示 `verify-upgrade@example.com`，账号空间按 schema 32 新建，`PRAGMA user_version` 为 32，`local_memory_use` 存在而 `memory_use` 已删除。模拟器在默认 GPU 设置下不显示 Flutter 画面，改用 `swiftshader_indirect` 后正常，判为模拟器渲染问题。

V1–V11 在模拟器上的逐条记录由缪鹏按 [02 第 8 章](02-产品与交互.md#8-验收标准)执行，本版发出之前没有做完，发出时只有上一段的升级与同步走查记录，验收结果在发出之后补进 02 第 8 章，补出的缺陷照常按 Issue 登记；这个缺口是提前发版的代价，理由见开头。第 3 节的 11 条改动已于 2026-11-24 逐条对照代码，行为都已落地：三类的记忆分栏、命名版本只剩名字时的副标题、两个改名后的危险操作与 Responses 这条链路都在代码里核过，仍要在模拟器上看一遍实际效果。核对时发现四处文案与说明不一致，已在同一次提交里改成一致：数据版本页的“清理历史”改为“清理本机历史”，只剩名字的版本按界面原文写作“该版本的历史不在本机，需要长期保留时请导出版本库备份”，同步失败提示里的“清除云端数据”改为“清除全部数据”，模型名与上限按设置页的实际做法改写。核对中提出的四处代码问题已在同一次核对里修掉并关闭：[#15](https://github.com/BUPT521/zhixin/issues/15) 完整性检查的核对条数改按检查点到 `HEAD` 这一段统计，[#16](https://github.com/BUPT521/zhixin/issues/16) 账号页的差异表改按中文表名显示，[#17](https://github.com/BUPT521/zhixin/issues/17) 记忆页手动写入改按 200 字校验，[#18](https://github.com/BUPT521/zhixin/issues/18) 记忆使用表的唯一键登记进远端冲突处置。四处都不改变本版的功能范围。

真实模型下的回答质量对照评测尚未运行，本版不作为发布门槛。Windows 开发机上的账号页全量用例曾出现既有停滞，合入时以 Linux CI 的结果为准。
