# 0.3.0 发版说明

> 0.3.0 是首轮内测包，把 0.2.0 之后的表结构变化、同步与模型链路的改动合成一次发出。本版按 [ADR-0017](adr/0017-表结构变化仍清空数据.md) 清空客户端各空间的本机库，服务端已在 2026-11-23 按 [ADR-0057](adr/0057-服务端改表清空重建.md) 整份重建，没有迁移，也没有兼容分支。发布日期、安装包字节数与 SHA-256 在发出时补到本节，版本名 0.3.0，构建号 4，标签 `v0.3.0`。

## 1. 这次清空了哪些数据

| 位置 | 清空的内容 | 保留的内容 |
|---|---|---|
| 客户端 | schema 28 的本机库，包含学习记录、图片、语义索引与这个账号空间的设置；升级后第一次打开时按 schema 31 重建。0.2.0 的 `filesDir/zhixin.db`、`image_cache/` 与 `vector_index/` 这套单体布局不再读取 | 账号、登录状态与服务地址在 Keystore 与 `cloud.json` 里，不在库里；设备标识保留 |
| 服务端 | 2026-11-23 15:43 按 schema 31 重建，账号、会话、验证码、提交序列、快照、设备名册、命名版本、备份元数据、附件索引与按账号的额度覆盖全部清空 | 模型来源、模型、路由与两张实例级的用量表，来源 key 仍用同一个 `ZHIXIN_SECRET_KEY` 解密 |

## 2. 升级之后要做什么

1. 重新注册并登录。服务端的账号已经随 11-23 的重建清空，旧账号、旧密码与旧令牌都不再存在。
2. 需要留下的学习记录、图片与讨论，请在升级之前用 0.2.0 导出版本库备份或数据包，留作核对；0.2.0 的包不能导回 0.3.0，恢复入口只接受当前结构（客户端 schema 31）的包，版本不一致的包在替换之前被拒绝，原数据保留。
3. 把同一账号在其他设备上也升级到 0.3.0。同步契约把推送与拉取载荷里的 `request_id` 改名为 `uid`，并增加逐条序号与可选的分表摘要，旧客户端与新服务端互不认识，两端要一起升级；服务端用 `/readyz` 报告的 schema 版本判断，版本不一致时直接说明两端要一起升级。
4. 重新设置课表、材料与外观。它们随账号空间保存，空间重建之后回到默认值。

## 3. 这一版改了什么

- 本地库按账号分空间：一个账号一个空间，切换账号不再把上一份记录带过去，也不反复整份上传；退出登录可以保留或删除这个账号在设备上的数据，“清除云端数据”改名为“清除全部数据”，“清理历史”改名为“清理本机历史”（[ADR-0056](adr/0056-本机数据按账号分空间.md)）。
- 命名版本随账号同步，换设备之后能看到名字；名字指向的提交已经不在本机时显示为“只剩标签”，注明该版本的历史不在本机，需要长期保留时请导出版本库备份（[ADR-0054](adr/0054-数据版本位置标记补强.md)）。
- 一致性摘要按表拆开比较，不一致时账号页写明哪几张表不同，并给出“以本机为准重建云端”一个入口（[ADR-0045](adr/0045-同步两端的一致性摘要.md)、[ADR-0054](adr/0054-数据版本位置标记补强.md)）。
- 数据完整性检查改为从最近的检查点重放到 `HEAD` 比对摘要，不再维护提交哈希链（[数据库结构过度设计审查](数据库结构过度设计审查.md) S1、S10）。
- 记忆改为自由文本条目，按情景、语义、程序三类组织，删除改为改状态；写入查重、主动搜索与“很久没用到”的整理建议要用的字段与使用统计已经建好（[ADR-0051](adr/0051-记忆改为自由文本条目并走文档检索路径.md)）。
- 同步接入快照压缩：服务端声明压缩开启时客户端上传整库快照，服务端历史被压缩之后，首次同步与遇到 410 的设备按快照浅克隆或重新克隆（[ADR-0043](adr/0043-服务端快照登记与提交序列压缩.md)、[ADR-0046](adr/0046-客户端按快照浅克隆与重新克隆.md)、[ADR-0047](adr/0047-快照附件回收与压缩前的客户端门槛.md)）。内测实例已于 2026-11-23 打开 `ZHIXIN_SYNC_COMPACT`（`KEEP=720h`）。
- 聊天接口统一成 OpenAI 现行的 Responses 格式，模型名与上限由服务端配置，客户端不再发送 Chat Completions 的字段（[ADR-0052](adr/0052-客户端改用OpenAI现行请求格式.md)、[ADR-0055](adr/0055-模型调用协议与上限统一.md)）。服务端部署之后，仍在用 0.2.0 的客户端聊天会失败，需要一起升级。
- 云端备份的上传与下载改为流式，导入包增加条目数与解压总量预算（[技术审查清单](项目技术审查与整改清单.md)的 DATA-01、DATA-02）；检查更新不再预先下载安装包，用户确认后由系统浏览器下载一次（UPDATE-01）。
- 嵌入来源只剩知新服务与本机哈希两项，查询向量也走云端（[ADR-0049](adr/0049-嵌入统一走百炼与查询向量也走云端.md)、[ADR-0050](adr/0050-客户端统一为知新服务.md)）。

## 4. 这一版还没做的

- 记忆的增改删三个工具、写入时合并近似条目、`search_memory`、三层召回预算与“很久没用到”的整理建议排在 M3，按[长期记忆整理方案](长期记忆整理方案.md#6-实施顺序)的顺序推进；这一版先把表建好，写入仍限 200 字。
- 预约提醒与日程导出按 [ADR-0020](adr/0020-预约提醒用本地通知与日程导出用ICS.md) 排在后面，本版表结构不为它们预留列。
- 首次使用引导、课表导入、分享到知新与人格插件对内测用户开放排在 M3，本版不包含。
- 记忆的语义检索按 ADR-0051 决定第 10 条沿用全文检索；查询向量虽已走云端，记忆条目本身不嵌入。

## 5. 验证与已知问题

客户端的格式检查、`flutter analyze`、全量单元测试（本机 1200 多个用例），服务端的 `gofmt`、`go vet` 与全量测试在推送之前都通过；两台独立客户端实例在 2026-11-23 走查了基线上传、快照登记、压缩、410 重建与双向同步，全部通过。V1–V11 在模拟器上的逐条记录由缪鹏按 [02 第 8 章](02-产品与交互.md#8-验收标准)执行，本版发出之前以验收记录为准，新增的三类记忆分栏、命名版本“只剩标签”与两个改名后的危险操作还没有逐条记录。真实模型下的回答质量对照评测尚未运行，本版不作为发布门槛。Windows 开发机上的账号页全量用例曾出现既有停滞，合入时以 Linux CI 的结果为准。
