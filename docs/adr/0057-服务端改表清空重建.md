# ADR-0057 服务端改表清空重建

## 状态

已采纳。2026-11-23 定，写入数据库结构过度设计审查第 7 节。本条只补一条一直没有写进文件的处理方式，不改动任何表。

## 日期

2026-11-23

## 背景

客户端的表结构变化在 [ADR-0017](0017-表结构变化仍清空数据.md) 里写清了：内测与公测期间一变就清空重建。服务端没有对应的条目。服务端的库由 `store.go` 按 `schema.sql` 整份重建，重建会把 `app_user` 在内的全部表一起清空，也就是说没有按列、按表迁移的能力。这个事实在讨论表层改动时被反复提起：每次要改服务端表，就得在“清空全部内测账号重建”和“另写一次性的变更脚本”之间选一个，于是审查里一直挂着一行“待确认”。用户已经多次说明按前者处理，但一直没有写进文件，所以换一台电脑的人看到的仍然是待确认。按 [AGENTS 第 3 节](../../AGENTS.md#3-决定写进文件)的口径，只在聊天里说过、没有写进文件的决定等于没定，本条就是把这个决定写下来。

当时的条件：内测刚刚起步，0.2.0 定在 2026-12-21 发出，内测者人数少且集中在团队附近，重新注册的成本主要是重新导入材料与课表，不是学习记录本身。开发阶段按 [ADR-0001](0001-开发阶段不向下兼容.md) 不承诺向下兼容。

## 决定

1. **服务端改表一律清空全部内测账号重建。** 不写按列的变更脚本，不为某次改表保留旧数据。改表之后由管理员停服、按新的 `schema.sql` 重建库、重新启动，全部账号与数据清空，内测者重新注册。

2. **每改一次都要在发版说明里写明。** 发版说明列出这次清了哪些账号数据、内测者需要重新做什么，例如注册、导入课表与材料。写明之后，内测者的成本是可预期的；不写，下一个人就不知道自己的数据为什么没了。

3. **“暂不动”的条目以后要做，同样按这一条处理。** 数据库结构过度设计审查第 4 节里暂时不动的服务端条目（V5、V6、V8、V10、V11）不再需要各自等一个“怎么改表”的结论，做的时候按清空重建执行，安排在不得不改表的那一次一起做。

4. **客户端不受影响。** 服务端清空不改变客户端的处理方式：客户端在服务端重建后按首次基线重新上传，本地数据保留。清理账号之后本机还可以继续用，重新注册即可。

## 代价与边界

- 每次改服务端表都会丢掉全部内测账号。内测者要在发版后的几天里重新注册、重新导入材料，试用节奏被打断；这是选清空重建而不是写变更脚本换来的确定性与省下的人力。
- 发版说明漏写一次，就会有内测者在不被告知的情况下面临登录失效。这条没有技术手段兜底，只能靠发版流程；写进本条是为了让流程上必须写。
- 内测人数增长到重新注册成为用户反馈的主要来源时，这条要重新评估。判断依据是发版之后询问“为什么登录不了”的人数，而不是预设的阈值。
- 服务端的账号级数据里，[ADR-0028](0028-服务端加固的默认拒绝与预算.md) 的登录会话、设备名册与命名版本（[ADR-0054](0054-数据版本位置标记补强.md)）都会随库一起丢掉。设备名册与命名版本会在下次同步时按客户端内容重新建立，会话需要重新登录，这些都不需要额外处理。

## 替代方案

- 写一次性变更脚本：每次改表写一段 `ALTER TABLE`，保留账号与数据。没有采纳的原因是服务端表之间外键密集，改一次往往牵动多张表与索引，脚本要单独写、单独测，还要处理执行到一半失败的情况；按现在的规模，省下的重新注册时间抵不上写与核对脚本的时间。
- 引入迁移工具（例如 goose、atlas）把变更脚本管起来：没有采纳的原因与上一条相同，另外还要维护版本号、基线快照与回滚策略，属于只有一个人维护的项目不划算的长期投入。
- 改表时只清空受影响的表：服务端表多数通过外键互相连接，清空一张表会连带级联删除，实际清空范围很难控制，比整体重建更难解释。不采纳。
- 内测者数据在重建前导出、重建后重新导入：导出与导入本身就要先有稳定的数据格式，而开发阶段格式还会变；导入还会把与新表结构不兼容的旧数据带进来。不采纳，改为发版说明里提示需要保留的内容用数据包留在本机。

## 影响

- 文档：[数据库结构过度设计审查](../数据库结构过度设计审查.md) 第 2 节“服务端改表另有代价”与第 7 节已确认的一条；[04 的 D1](../04-长期路线图.md) 补服务端与表；[ADR 索引](README.md)。
- 流程：发版说明固定列出“本次清空了服务端账号数据，需要重新注册”这一项；`store.go` 的重建入口就是执行点，不需要新代码。
- 既有决策：本条不改 [ADR-0017](0017-表结构变化仍清空数据.md) 对客户端的规定，只补服务端这一侧，与 ADR-0017 的 D1 一并执行。
