# ADR-NNNN 标题

## 状态

提议

## 日期

YYYY-MM-DD

## 背景

写清作出这个决定时面对的问题、已经试过的做法与当时的条件，包括团队规模、时间、数据是否可以丢弃这些会改变判断的事实。背景只写当时成立的内容，不写后来才知道的结果。

## 决定

写清最终执行的做法，一条一段。涉及范围、边界与否定的内容写进句子里，不留给读者从上下文推测。

## 代价与边界

写清执行这条决定要放弃什么、哪些数据或行为会受影响、什么情况下需要重新评估。代价写得越具体，后来的人越容易判断这条决定是否仍然成立。

## 替代方案

写清考虑过但没有采纳的做法，以及没有采纳的原因。没有考虑过其他做法时写“没有考虑其他方案”，不要留空。

## 影响

列出需要同步修改的文档、代码与流程，每项附相对链接。ADR 本身不复制这些内容，只指出它们在哪里。
