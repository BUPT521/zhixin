# ADR-0016 对象存储用 S3 兼容接口保存备份与附件

## 状态

已采纳。整库备份的字节已经改走对象存储抽象，`/v1/blobs` 的上传、下载与存在检查按契约实现；S3 路径已通过本地 MinIO 与 PostgreSQL 联调，结果见 [server/README](../../server/README.md#本地运行与检查)。

## 日期

2026-11-15

## 背景

[ADR-0009](0009-API后端采用Go与分层框架.md) 第 4 条把附件与整库备份定在 S3 兼容的对象存储里，自建时用 MinIO；[ADR-0015](0015-服务端引入代码生成与限流依赖.md) 之后，账号、会话、提交序列与用量已经入库，只剩字节还写在 `ZHIXIN_BLOB_DIR` 的本地目录里，`/v1/blobs` 的三条路径注册的是 501。[server/README](../../server/README.md) 把“对象存储与 `/v1/blobs`”排在这一批，[轮子与技术选型评估第 3.6 节](../轮子与技术选型评估.md#36-附件与备份走预签名地址) 建议用 `minio-go` 签发预签名地址、让客户端直传。

现在要做的是决定客户端怎么拿到对象存储、键怎么排、没有对象存储时怎么办，以及预签名直传是否在这一步就换。

## 决定

1. 客户端用 `github.com/minio/minio-go/v7`。它是单一模块，路径风格、SigV4 签名与分块上传都由库负责，自建的 MinIO 与阿里云 OSS、腾讯云 COS 这类兼容接口可以只换 endpoint 与密钥；官方的 `aws-sdk-go-v2` 要拆成多个模块，S3 兼容地址还要额外配置端点与路径风格，收益只在国内厂商适配更细，内测一台 MinIO 用不到。ADR-0009 第 1 条的依赖清单按本条更新：第三方依赖在 `x/crypto`、`pgx/v5`、`x/time` 之外增加 `minio-go/v7`。
2. 字节仍经 `zhixin-api` 转发，不改成预签名直传。契约里的三条路径已经按“服务端收发字节”写成，客户端的登录与备份还没接，现在换形态要同时改契约、服务端与尚未写出的客户端；预签名还要求对象存储对客户端可达，公网地址、证书与 CORS 都要单独配，内测的一台机器还没到这一步。评估第 3.6 节的建议留到客户端接附件、备份包的带宽成为实际瓶颈时再评估，届时按新的契约改动。
3. 键按账号隔离：整库备份是 `backups/<账号>/<id>.zip`，附件是 `attachments/<账号>/<sha256>`，删除账号时按前缀清掉。附件按内容寻址，同一账号重复上传相同内容写到同一个键，结果不变；不同账号之间不共享对象，存在性检查也因此不能用来探测别的账号。
4. 存放位置按配置决定：设置了 `ZHIXIN_S3_ENDPOINT` 就用 S3 兼容存储；没设置而设了 `ZHIXIN_DATABASE_URL` 时用 `ZHIXIN_BLOB_DIR` 指定的本地目录，保证没有对象存储的机器也能联调；两者都没有时用内存实现，与其余存储一致，退出即丢。
5. 写入先落到临时位置再移到最终键：本地目录写临时文件后改名，S3 由服务端把请求体写到临时文件、核对哈希之后再上传。声明的大小与实际字节数不符时拒绝，读取方不会看到写了一半的对象。
6. 上传经 `httpx.SpoolBody` 落到临时文件，同时算出 SHA-256。备份最大 256 MB，附件上限可配，放进内存会随并发上涨，所以统一走临时文件；临时目录要有足够空间。
7. 单个附件的上限是 `ZHIXIN_MAX_ATTACHMENT_BYTES`，默认 32 MiB。每账号的总容量、附件的保留期、是否跨账号去重都待定，不在本条里定。
8. 常规自动化用例使用内存与本地目录实现。S3 路径使用专用 MinIO 与 PostgreSQL 实例联调，上传、下载、备份保留与删号清理的结果记在 [server/README 的本地运行](../../server/README.md#本地运行与检查)。

## 代价与边界

- 多了一个运行时依赖 `minio-go/v7` 与它的间接依赖，编译时间与依赖面比只有标准库与 `pgx` 时大；`go mod tidy -diff` 的 CI 步骤照旧，提交前要重新生成。
- 字节经 API 转发，进程要承担备份包的带宽、临时磁盘与连接时长；并发上传多个 256 MB 备份时，临时目录与出口带宽是先撑不住的地方。预签名直传能避开这一点，但本条决定把它推后。
- 对象存储不可达时，备份上传、附件读写都会失败，`/readyz` 会返回 503；endpoint、bucket 与密钥全部来自环境变量，仓库里不保存。
- 附件与备份的本地目录实现仍然保留，用于没有 S3 的开发机；两套实现共用同一套键与接口，切换只改配置，但本地目录不是部署形态，内测服务器必须配 S3。
- 本地联调覆盖 S3 的分块上传、读取、按键删除与按账号前缀清理；部署环境仍需核对 TLS、bucket 权限与实际备份容量。
- 开发阶段不写迁移：此前写在 `ZHIXIN_BLOB_DIR` 的备份按 [ADR-0001](0001-开发阶段不向下兼容.md) 视为可丢弃的测试数据，换到 S3 时不搬运，也不留兼容分支。

## 替代方案

- 用 `aws-sdk-go-v2` 的 S3 客户端。没有采纳的原因是模块多、S3 兼容地址要额外配置端点解析与路径风格，而本项目只需要按账号存取几个对象的字节，`minio-go` 的接口更直接。
- 用预签名地址让客户端直传直取。这是评估第 3.6 节的建议，没有在这一步采纳，原因是契约、客户端与部署配置要同时改，而客户端的登录与备份还没开始；等附件真正接入、带宽成为瓶颈时重新评估。
- 自己实现 SigV4 与分块上传。没有采纳的原因是签名、重试与分块边界都要自己维护，出错只在大文件上暴露，维护成本高于引入一个成熟的客户端库。

## 影响

- 服务端：新增 `server/internal/objectstore`（S3、本地目录与内存三种实现）与 `server/internal/blobs`（附件接口与存储），[internal/httpx/spool.go](../../server/internal/httpx/spool.go) 提供落盘与哈希，备份处理器与 `store/pg` 改用它。[config](../../server/internal/config/config.go) 增加 `ZHIXIN_S3_*` 与 `ZHIXIN_MAX_ATTACHMENT_BYTES`，[api/openapi.yaml](../../server/api/openapi.yaml) 去掉 `/v1/blobs` 的“返回 501”，[api/cfg.yaml](../../server/api/cfg.yaml) 的输出路径改成相对 `server/` 的写法，使 CI 的重新生成落在 `internal/api/`。
- 检查流程：`server/README` 的配置表与目录说明、[选型实施规划第 6 节](../选型实施规划与提示词.md#6-未完成事项盘点) 的状态、[04 第 1 节](../04-长期路线图.md#1-现状) 的服务端现状。
