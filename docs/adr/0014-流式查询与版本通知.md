# ADR-0014 流式查询与版本通知

## 状态

提议

## 日期

2026-11-14

## 背景

页面在写入之后手动重读数据，`await _load()` 在全项目有 62 处，`plan_page.dart` 一个文件里有 18 处，`setState` 共 274 处。[ADR-0007](0007-首屏预读缓存与失效.md) 用 `dataVersion` 与进程内提交序号判断首屏预读是否失效，覆盖恢复、清空、导入、撤销与每日截止小时变化，普通新增、编辑、删除则靠各页面自己记得重读。这套做法有两个已知问题：漏掉一处重读，页面就停在旧数据上；把重读加满，每次写入又会重复查询已经读过的结果。

drift 的流式查询提供同一种能力：查询以 `.watch()` 订阅，相关表一有写入，drift 重跑查询并推送新结果。本项目的写入多数经 `customStatement` 一类原生 SQL 进入，drift 不知道它们改了哪些表，所以现在订阅流不会收到任何更新。版本引擎知道：每次提交收尾时，净变化已经按表归类。

评估见 [轮子与技术选型评估第 2.4 节](../轮子与技术选型评估.md#24-用流式查询代替手动重读)。

## 决定

1. 仓库层在 [ADR-0011](0011-仓库查询改用drift生成代码.md) 完成之后，为需要跟随写入更新的查询提供流式版本（`.watch()`），页面改用 `StreamBuilder` 订阅，不再在写入之后手动 `_load()`。
2. [RevisionEngine.finishCommand](../../app/lib/data/revisions/revision_engine.dart) 在合并净变化之后，对本次提交涉及的每一张业务表调用一次 `notifyUpdates`，通知发生在事务提交之后、`GuardedDatabase` 释放独占访问之前，与 ADR-0007 推进提交序号的时机相同。没有净变化的命令不通知。
3. 撤销、恢复、清空与导入在独占区结束时对全部业务表通知一次。
4. 没有净变化但仍然修改了业务行的写入（例如写入值与现值相同）不通知。这种情况下页面显示的内容不变，跳过通知不会让界面停在旧数据上。
5. 状态管理不引入 Riverpod 一类框架，`StreamBuilder` 加现有的 `AppScope` 已经够用。ADR-0007 中“首屏多次查询共用共享访问范围”与“页面等转场结束再回填”两条时序约束继续由页面保留，drift 不替代它们。
6. 先在“安排”或“记录”一页试做，确认与 `DatabaseGate` 的读写协调、恢复时的执行器替换都不冲突，再推到其他页面。

## 代价与边界

- 通知按表发送，粒度比页面需要的粗：一张表被写入，所有订阅这张表的页面都会重跑查询。本项目的页面数量少，查询结果集小，这个粒度可以接受；如果后续出现多个页面订阅同一张大表，需要再细化到按行或按查询的通知。
- 每条流查询在页面存活期间会多一次结果缓存与比对，内存占用与页面数量成正比。长列表仍要分页，不能因为改用流就把整表读进页面。
- 恢复时执行器会被替换，现有的流订阅在替换后指向旧执行器。恢复流程要先让订阅结束再换连接，或者在换连接之后对全部业务表通知一次并重建订阅，这一条要在试做页面上验证。
- 页面从手动重读改成订阅之后，加载状态、错误状态与空状态的显示逻辑要重写一遍，测试里等待页面更新的方式也要从“等待一次 `_load`”改成“等待一次推送”。
- 这一项依赖 ADR-0011 的生成代码，实施顺序排在仓库迁移之后；如果仓库迁移没有完成，本条目不启动。

## 替代方案

- 继续用 `dataVersion` 加提交序号，要求每个写入入口都推进一次版本号。没有采纳的原因是这一点与 ADR-0007 已经选择的“提交收尾统一推进”重复，而且页面仍需自己决定何时重读。
- 让每次写入都手动通知全部表。没有采纳的原因是通知范围与代价都最大，页面会收到与自己无关的刷新。
- 把写入路径全部改写成 drift 的 Dart DSL，由 drift 自动推断受影响的表。没有采纳的原因是版本引擎、备份与恢复依赖原生 SQL 与触发器，ADR-0004 已经否掉了改写。

## 影响

- 数据层：[revision_engine.dart](../../app/lib/data/revisions/revision_engine.dart)、[guarded_database.dart](../../app/lib/data/db/guarded_database.dart)、[revision_service.dart](../../app/lib/data/revisions/revision_service.dart) 与仓库层的流式方法。
- 界面：先试做页面的 `_load()` 与 `setState` 调用点，逐步扩展到其他页面。
- 文档：[ADR-0007](0007-首屏预读缓存与失效.md) 中“按版本号判断失效”的部分由本条取代，[评估第 2.4 节](../轮子与技术选型评估.md#24-用流式查询代替手动重读)。
