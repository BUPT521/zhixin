# ADR-0024 关键词检索并入 zvec

## 状态

已采纳。2026-11-17 完成索引表、触发器与查询的删除，文档与测试同步改写。

## 日期

2026-11-17

## 背景

[ADR-0013](0013-关键词检索改用FTS5.md) 把关键词检索换成业务库里的三张 FTS5 表，用触发器在同一次 SQLite 事务里跟着业务行更新，查询用二元组 `MATCH` 与 `bm25()` 排序。语义检索在 [ADR-0022](0022-语义索引改用zvec.md) 里换成了 zvec，两路结果由应用层的 `fuseSearch` 按名次倒数相加合并。两路各有一套候选截断：本地窗口 2000 条，语义候选按范围放大到 `limit × 20` 并封顶 400。

zvec 0.8 的 Dart 包已经能在一次 `MultiQuery` 里同时发起全文子查询与向量子查询，用 `RrfRerank` 或 `WeightedRerank` 在引擎内融合，每个子查询可以单独设 `numCandidates`。继续保留两套索引意味着两套候选、两套截断与一套跨存储的合并规则，每一次调整排序都要同时改两边。

但关键词检索不能跟着嵌入配置走。[ADR-0013](0013-关键词检索改用FTS5.md) 的替代方案一节已经说明，未配置嵌入模型时检索仍要可用；现在的语义索引只在配置了嵌入来源之后才打开，把关键词直接搬进去会让这些用户失去关键词检索。zvec 的 collection schema 在创建时固定，向量字段的维度又随模型变化，所以本条要求索引始终维护，schema 按当前是否配置模型生成。

## 决定

1. 关键词检索并入 zvec：每个片段的正文写进 collection 的 `content` 字段并建立 FTS 索引，检索时一次 `MultiQuery` 发起全文子查询与向量子查询，融合用 `RrfRerank`，平滑常数沿用 60。
2. collection 的 schema 随嵌入配置生成：没有配置模型时只有 `content` 与标量字段，配置之后加上向量字段并换一个目录重建；索引始终维护，刷新不再以“配置了嵌入来源”为条件，没有配置模型时只做本地读写，不产生网络调用。
3. 检索按配置分流：配置了模型时发一次 `MultiQuery`（全文与向量，引擎内融合）；没有配置时只发全文子查询，按 BM25 排序。两种情况返回同一种结果结构。
4. 删除三张 FTS5 表、它们的触发器与 `MATCH`、`bm25()` 查询；字面命中仍由业务库的 `instr` 完成，不经索引，四类来源的读取与限条数不变。
5. 范围条件复用现有的预过滤渲染，接到 `MultiQuery.filter` 上；能下推预过滤时按 `limit × 4` 取候选，目标范围不能下推时保留 `limit × 20` 并封顶 400，避免收窄范围之后漏召回。
6. 融合的最后一步留在应用层：`fuseSearch` 的接口不变，按记录键聚合，同一来源的多个片段只保留最好的一次名次，字面命中仍然置顶；`SearchService` 不再为语义候选单独放大，记录页带索引命中时本地窗口只取字面命中，索引给出的候选只参与一次融合。
7. 索引刷新沿用现有的 3 秒静默期与按数据代次整份重建；collection schema 变化时旧目录直接废弃重建，不做迁移，符合 [ADR-0002](0002-本地数据不做迁移.md)。
8. 服务层测试继续使用内存索引，`MemoryVectorIndex` 增加与 zvec 同口径的关键词匹配，契约测试用同一组输入比较两种实现；需要真实引擎的用例仍由 `ZVEC_LIBRARY_PATH` 决定是否执行。

## 代价与边界

- 关键词检索继承索引的滞后：最后一次写入之后要等 3 秒静默期，再加扫描与嵌入的时间，这段时间里刚写入的记录既搜不到关键词也搜不到语义。现有语义检索已经是这个节奏，本条把它扩展到关键词，界面不额外提示。
- 没有配置嵌入模型的用户也会在本地维护一份 zvec 文本索引：内存上限、索引目录与重建成本随之扩大到全部用户，换来的是关键词检索不再依赖业务库的 FTS5，也不依赖嵌入配置。
- 配置与不配置之间切换时 collection 的 schema 不同，每次切换都要整份重建文本索引；重建只读业务库，不调用嵌入服务，代价是扫描与写盘，不是计费。
- 索引打不开、损坏或重建期间，关键词与语义一起不可用，只剩字面命中与原文。ADR-0022 决定第 9 条的降级范围由此扩大，这是删除 FTS5 之后无法避免的。
- 分词口径从二元组换成 zvec 的 jieba，两字词、英文缩写、代码符号与公式的覆盖会变，评测集要重新复核前几条结果；`search_terms.dart` 的 `bigrams` 保留给字面高亮与记忆正文排序使用，不再服务关键词索引。
- 关键词得分不再是 `bm25()` 的原始值，`keywordMatchScore` 的换算随之删除，命中一路的分数由引擎的融合分代替；界面上的“按意思”标签仍由命中的来源决定，不依赖分数。
- 删除 FTS5 会让业务库少一份分词与位置索引，写入时也不再按字符展开正文，材料页批量导入的写入耗时下降；这部分收益没有计入本条的取舍。

## 替代方案

- 保留 FTS5，只把语义索引换成 zvec。这是现在的做法，没有采纳的原因是每次调整排序都要同时改两套候选与跨存储的合并规则，两边的截断口径也不一致。
- 保留两份关键词索引，迁移期双写对照。没有采纳的原因是对照只需要在实施阶段做一次，不做成长期结构；双写要维护两份一致性，收益只在迁移窗口内。
- 用 `WeightedRerank` 做分数级融合。没有采纳的原因是 BM25 无界、FTS 字段没有度量，归一化口径要先验证再调权重，而 RRF 与现有的名次融合口径一致，迁移前后的顺序可以直接对照。
- 把关键词做成稀疏向量，在 Dart 侧按 IDF 计算权重。没有采纳的原因是要自建词表映射与语料统计，等于再写一份 BM25，与 zvec 的 FTS 重复。
