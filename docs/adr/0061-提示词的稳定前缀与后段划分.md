# ADR-0061 提示词的稳定前缀与后段划分

## 状态

已采纳（2026-11-24，2026-11-26 改动分界位置）。落实 [模型调度与回答恢复实施方案](../模型调度与回答恢复实施方案.md) 第 5 节的提示词构建与缓存复用，承接 [ADR-0060](0060-一轮回答的预算与按讨论分配来源.md) 的按讨论分配来源。

## 日期

2026-11-24

## 背景

按讨论分配来源之后，同一条讨论的追问与工具步骤会落到同一条模型来源，上游有机会复用已经处理过的输入前缀。但系统提示此前把“当前时间”放在规则与人格之后、目标与材料之前：同一讨论里每一分钟都会换一次时间，时间之后的目标、材料与范围随之整段变化，前缀命中不了，按讨论分配来源的收益也就落空了。方案第 5 节要求把稳定指令、顺序固定的工具定义与仍适用的历史放在前缀，把当前时间、本轮检索与记忆结果和本轮问题放在后段。

2026-11-26 的补充来自同一条约束的下一步：分界放在系统提示内部仍然不够。代理把整段系统提示放在请求的 `instructions` 里，`instructions` 排在全部历史消息之前，于是“当前时间”之后的内容一变，不只是系统提示的后半段，后面整段历史消息也要重新处理。同一讨论的追问只要换一分钟，前缀复用就只剩规则与材料那一小段。因此分界从系统提示内部移到请求本身：`instructions` 只保留稳定前缀，本轮内容随这一轮的用户消息发出。

## 决定

1. 系统提示只保留稳定前缀：介绍、规则、人格、讨论归属、材料与系统学习范围。请求的 `instructions` 就是这一段，同一讨论的每一轮与每个工具步骤都逐字相同。
2. 从当前时间开始的内容依次是对话焦点、材料命中、相关记录、原文证据、题目与作答、跨次说明、最近作答与记忆；这些内容随这一轮的用户消息一起发，排在用户原话之前，模型读到的先后顺序与之前放进系统提示时相同。
3. 工具定义按注册顺序固定发送，本轮不用的工具不出现，出现时顺序不随请求变化。
4. 稳定前缀不因本轮内容多少而增删：记忆用法与记忆冲突两条规则在该用途下始终出现，不再按“本轮有没有检索到记忆”增删，否则同一讨论的 `instructions` 会在轮与轮之间改变。
5. 上下文超出预算时仍按原有规则删减，删减只发生在后段；历史消息按保存的原样重发，本轮内容只追加在末尾。
6. 用例钉住这条边界：以“当前时间：”为界，前面两段相同内容生成的提示词必须逐字相同，时间与记忆只能出现在它之后；分段之后，前缀段不含时间，本轮段以时间开头，两段拼起来与整段逐字相同。

## 代价与边界

分界移到请求本身之后，历史消息里保存的是用户原话，不含那一轮的上下文段，因此每轮复用最多接到上一条用户消息为止：上一轮的时间与检索结果按当时的文字发出过，这一轮重发的历史里没有它们，前缀在这一条上重新开始。最近一轮重新处理换来的是更早的整段历史继续命中，讨论越长收益越大。把时间与上下文移到后段不会减少提示词总长度，缓存收益取决于上游是否按前缀命中与最小可缓存长度，具体比例要按真实调用采集（方案第 7 节）。前缀段包含目标与材料，用户切换目标、材料或页码时前缀本来就会变，这一段命中不了属于预期。本轮上下文进入用户消息之后，模型会把它当作随问题一起提供的材料，题目与记忆离指令更远，答案风格与引用习惯要按方案第 7 节的质量抽检验证，发现退化时先调整本轮段内的顺序与措辞，不回退到把本轮内容放进 `instructions` 的做法。

## 替代方案

- 只保留现状、不动顺序：前缀每分钟失效一次，按讨论分配来源的缓存收益几乎为零，没有采纳。
- 把整套上下文都移到后段、前缀只留规则：前缀更短、更容易命中，但材料与范围离问题太远，讲解与引用质量会下降，没有采纳。
- 前缀里再剔除目标与材料、只留规则与人格：命中率更高，但两个用户共用同一来源时前缀会互相覆盖，收益按账号摊薄之后没有明显优势，也没有采纳。
- 把本轮上下文与用户原话一起保存进历史，下一轮原样重发：前缀可以接到上一条消息之后，但要给消息表加一列并进入同步载荷，涨出的是表结构与数据版本的工作量，没有采纳。
