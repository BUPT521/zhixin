# ADR-0093 同意对话框改在进入应用时弹出

## 状态

已采纳。2026-11-29 与实现同批生效。取代 [ADR-0092](0092-引导改为两步与按需同意.md) 决定第 2 条里的触发时机，其余决定不变：引导仍是两步，老用户与版本升级仍在首页上补同意，对话框的组成、设备文件与纯本机模式都按 ADR-0092 与 [ADR-0077](0077-首次启动引导与须知同意.md) 执行。文案同时改为书面表述。

## 日期

2026-11-29

## 背景

[ADR-0092](0092-引导改为两步与按需同意.md) 把同意放在点登录时询问，理由是同意与登录发生在同一个动作之前。实现之后登录页先出现，用户只有在点登录、注册或找回密码时才第一次看到两份文件的入口；不登录的人从头到尾不知道采集范围与联系方式，而这正是 ADR-0077 最初要解决的事。产品负责人看实现之后要求进入应用就告知，对话框的文案也要求正式一些。

## 决定

1. 进入引导（登录页）之后立刻弹同意对话框，标题写“用户须知与隐私政策”；已经同意过当前版本的设备不弹。老用户与须知版本升级的补同意仍在首页上弹同一个对话框。

2. 关掉对话框不算同意：留在登录页，仍可以点“先在本机用”；之后再点登录、注册或找回密码，会重新弹同一个对话框。

3. 对话框里的“仅在本机使用”与“先在本机用”效果相同：没有同意过时记下当前版本已经回答过、没有同意，直接到外观这一步。已经同意过的用户点“先在本机用”只是这次不登录，同意状态与匿名统计的开关都不变。

4. 对话框的文案用书面表述：标题写文件名称，正文写“需要阅读并同意这两份文件”与不同意的后果，勾选写作“本人已阅读并同意”，按钮写“同意并继续”与“仅在本机使用”；勾选框与匿名统计开关照旧。

5. 老用户与须知版本升级仍在首页上弹同一个对话框，版本升级时标题写“用户须知与隐私政策已更新”，回答过之后写完成标记。

## 代价与边界

- 用户第一眼看到的是一份需要勾选的对话框，登录表单退到后面；不愿意读的人会先关掉对话框，关掉之后界面上没有“还会再弹”的提示，只有点登录时才看得到。
- 进入即弹意味着第一屏多一个动作；点“仅在本机使用”或关掉对话框都只需要一次点击，不会挡住使用本机功能。
- 同意与不同意的记录方式、设备文件与联网边界都没有改动，重装或清除数据之后重新弹。
- 重新评估的条件：首次进入就关掉的比例高，或者隐私与上架要求改回进入即告知的强制停留时，再看是否把“仅在本机使用”做成更明显的入口。

## 替代方案

- 按 ADR-0092 在点登录时问：进入更安静，但用户可能一直不知道两份文件的存在，且与最初“进入即告知”的目标冲突。没有采纳。
- 进入即弹且不可关闭：边界更硬，但没读完之前用不了本机功能，与“不同意也能在本机使用”冲突。没有采纳。
- 弹窗里只放勾选、两份文件的入口留在设置页：对话框更短，但同意时看不到正文入口，明示同意的取证更弱。没有采纳。
