# ADR-0031 云端写入与托管模型的资源预算

## 状态

已采纳。本条更新 [ADR-0028](0028-服务端加固的默认拒绝与预算.md) 的预算、云端清除和发布校验规则，也更新 [ADR-0029](0029-模型来源路由与嵌入代理.md) 的模型结算与来源管理规则，以及 [ADR-0025](0025-应用内更新检查与反馈的接口口径.md) 的反馈容量规则。

## 日期

2026-11-19

## 背景

第一套实例与 PostgreSQL 共用 40 GB 磁盘和 1682 MB 内存。同步分页即使限制响应大小，也需要先限制数据库返回的数据量。模型请求应在转发前为输出和备用来源留出预算，因为连接断开或某批失败时，提供方仍可能收取已经完成的部分。云端副本可能是用户仅存的一份数据，所以清空时需要重新确认密码，并保证在途上传和清空按顺序完成。

## 决定

1. 启用 PostgreSQL 的实例要求账号确认邮箱后才接受同步、备份和附件写入。邮箱持有人可用重设密码验证码恢复尚未确认的账号，服务端在同一事务中用掉验证码、确认邮箱、更新密码并撤销旧会话。验证与重设发信共用按收件地址的预算。
2. 同步推送按账号限流，单条上限为 2 MiB，单次请求上限为 16 MiB，每账号提交序列预算为 256 MiB。PostgreSQL 在读取提交正文前按累计字节选取连续页，客户端按字节和条数分批推送。旧的超限提交返回 413。所有账号的同步推送和拉取合计最多同时处理四个请求，备份和附件临时文件共用 1 GiB 的在途预算。
3. 登录及删除类操作在核对密码前占用失败预算，核对成功后归还。批量清除云端数据、备份或同步序列都要再次提交当前密码。单个服务进程内，同账号的清除与写入互斥；有请求在途时返回 409，数据库中的清除标记负责中断后的重试。
4. 托管聊天只生成一个候选，输出最多 8192 token。每次转发前按请求字节与最大输出预留，流式转发由服务端要求用量，缺少用量时保留预留。嵌入按输入字节预留，已发出批次按有效用量或估算值结算，返回失败与切换来源时也结算已经发出的批次。生产后台配置的模型来源使用公网 HTTPS，来源密钥绑定完整地址，提供方错误正文留在提供方。
5. 匿名反馈与活跃上报先检查来源地址，再消耗实例额度。反馈诊断摘要上限为 64 KiB，实例最多保留 10,000 条反馈。发布清单必须有 Ed25519 签名，客户端在下载前用内置公钥验证签名，下载后核对安装包哈希。

## 代价与边界

同步配额按账号计算，所有账号的总容量仍由实例磁盘决定。单条本机提交超过同步限制时保留本机记录，由应用提示这次同步未完成。清除与上传的互斥范围是单个 API 进程，第一套实例按一个进程部署。反馈存满后暂停接收，直到保留期清理或管理员按保留政策释放空间。

按输入字节估算可能高于上游实计，内联图片的请求更明显。如果提供方返回的用量高于预留，服务端结算时补记。结果不确定的上游尝试会保留相应预算，避免提供方已经计费却漏记。上线前应验证 SMTP，因为没有发信配置时未确认的账号无法开放云端写入；旧地址规则加密的模型来源密钥需要重新填写。

## 替代方案

同步页在读取后再裁剪会保留整页正文的内存压力，因此改成先选序号再读取正文。清除时只复查标记仍会留下检查之后才写入的间隔，所以在整个请求期间保留每账号的互斥状态。托管请求在缺少用量时全部退回会低估提供方已完成的工作，因此按预留或已发出批次结算。
