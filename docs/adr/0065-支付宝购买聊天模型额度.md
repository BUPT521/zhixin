# ADR-0065 支付宝购买聊天模型额度

- 状态：已采纳，待支付宝沙箱验收
- 日期：2026-11-25

## 背景

知新原来只发放按日重置的免费模型额度。Android 应用需要允许用户一次性增加聊天额度，项目组也计划以后提供连续订阅，因此先接入支付宝 Vibe Pay 的移动应用收款能力。

## 决定

用户验证邮箱后可以在“账号与云同步”的“模型额度”一节购买聊天 Token 包。服务端配置一个可售档位，并在下单时固定整数分金额与 Token 数。同一账号在原订单可支付期间重试时继续使用原订单，订单有效期为十五分钟。Android 客户端用支付宝官方 SDK 打开收银台，支付后向知新服务查询结果。价格与 Token 数设为零时暂停新单，保留原支付配置即可继续查单和使用已购额度。

服务端只在支付宝异步通知或者主动查单验签通过、订单号与金额核对无误后确认到账，异步通知还要核对应用和商户身份。更新订单状态与增加余额在同一个 PostgreSQL 事务里完成，回调重发和同时查单都只增加一次额度。沙箱与正式余额分开保存。

模型代理预留和结算聊天用量时先计入每日免费额度，余量计入购买额度，嵌入仍按独立的每日额度计算。购买余额按账号保存，跨日保留，模型代理密钥与登录令牌使用同一余额，账号并发和实例预算照常生效。提供方未能返回实际用量时沿用现有预留口径，服务进程中断时也可能留下估算用量，需要在对账时核对。

平台订阅沿用知新账号及支付宝签名、验签和查单能力。Token Pay 的签约入口使用支付宝返回的跳转链接，订阅的生效、续费和取消依据订阅通知处理，具体商品、周期和权益规则待订阅接入时确定。[Vibe Pay 移动应用收款](https://aipay.alipay.com/docs/vibe-pay/mobile-app-pay/app-pay-integration-guide-new.html) · [Token Pay 个体订阅](https://aipay.alipay.com/docs/subscribe/integration-guide/individual.html)

## 上线条件

本次支持沙箱和正式参数，默认关闭收款。正式开通前，项目组需要完成商户签约、真机沙箱核验、退款与对账流程，并确认发版渠道的收款要求。删除账号时删除已购余额，订单按对账用途保留并解除账号关联。已有正式交易后，生产库的备份和恢复须一并保全账号、订单、钱包及当日用量，不能再依照开发库流程清空重建。
