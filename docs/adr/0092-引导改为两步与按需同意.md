# ADR-0092 引导改为两步与按需同意

## 状态

已采纳。2026-11-29 与实现同批生效。部分取代 [ADR-0077](0077-首次启动引导与须知同意.md)：三步引导改为两步，用户须知的同意从独立的第一页改为对话框；同意之前不发出网络请求、设备级存储、入口位置、换空间判定与共用登录表单继续按 ADR-0077 执行。决定第 2 条里的触发时机由 [ADR-0093](0093-同意对话框改在进入应用时弹出.md) 改为进入应用时弹出，其余决定不变。

## 日期

2026-11-29

## 背景

[ADR-0077](0077-首次启动引导与须知同意.md) 把首次启动定成三步，第一页专门放《用户须知》与《隐私政策》的入口、勾选与匿名统计开关。实现之后这一页在登录之前挡一整屏：用户第一次打开应用先看到一页说明，读完才见到登录表单，而同意与登录本来就发生在同一个动作之前，中间隔着一页卡片列表。0.4.0 之前重排引导的登录一步时，登录表单与两份说明的入口都已就位，第一页剩下的内容只有同意本身。

团队仍是四人，每周合计 32 小时，0.3.0 内测包尚未发出；开发阶段不承诺向下兼容（[ADR-0001](0001-开发阶段不向下兼容.md)），引导的步骤与设备文件里的取值都可以直接改。

## 决定

1. 引导改为两步：登录或注册、选择主题色与深浅色；顶部进度点两段，登录与外观都可以跳过。登录页是第一步，它没有“上一步”，返回键退出应用；外观这一步的返回键回到登录页，左右划动与底栏四栏共用同一套整页滑动。

2. 用户须知的同意不占一步。点登录、注册或找回密码时，如果设备文件里没有当前版本的同意，先弹同意对话框：两份说明的应用内页面入口、一个默认不勾选的“我已阅读并同意”、默认开启的“匿名使用统计”开关、“同意并继续”与“不同意，仅在本机使用”。同意之后继续这次登录或找回密码；关掉对话框只取消这一次，不写任何状态。

3. 老用户与须知版本升级不显示引导。启动时照常进入“现在”页，再在首页上弹同一个对话框，版本升级时标题写作“用户须知有更新”；回答过之后写完成标记，下次启动直接进入首页。关掉对话框就留在纯本机模式，联网功能保持关闭。

4. 登录页的“先在本机用”与对话框里的“不同意，仅在本机使用”效果相同：记下当前版本已经回答过、没有同意，直接到外观这一步。下次启动不再询问；之后在“我的”或账号页再点登录、找回密码，仍会弹同一个对话框。

5. ADR-0077 的其余结论不变：同意之前不发出网络请求，匿名上报与更新检查再等到引导完成；完成标记、须知版本、是否同意与当前步骤存在 `filesDir/onboarding`；引导入口在应用根部；第一次登录换空间之后按重建后的登录态判断这一步是否完成；账号页与引导共用登录表单，找回密码直接打开账号页的重设形态。

## 代价与边界

- 读到两份说明正文的时间推迟到第一次点登录；在此之前应用只在标题下说明“登录能得到什么”，不展示采集范围。
- 同意与不同意都绑定在登录动作上，关掉对话框等于取消这次登录，用户可能误以为点了没有反应，按钮与标题的文案要写清这一点。
- 老用户的补同意从“占一页、不能跳过”改为“盖在首页上、可以关掉”，关掉之后长期停留在纯本机模式，恢复入口在设置页。
- 纯本机模式下从“我的”再点登录仍会弹对话框，与设置页的同意入口并存，两条路径写的是同一份状态。
- 设备文件里旧的 `terms` 取值按登录页读取；开发阶段不写迁移，重装或清除数据即可。
- 重新评估的条件有两条：隐私或上架要求提出进入即告知、或在首页告知，此时改回进入即弹的对话框；纯本机模式的比例高到影响内测留存时，再看是否把同意放回登录卡里常驻。

## 替代方案

- 保留三步，只把第一页改成进入应用即弹的对话框：进入就被挡一次，登录与同意仍分在两处，对话框只是换了个形状。没有采纳。
- 把勾选直接放在登录卡里，不弹对话框：少一次弹窗，但两份说明入口与匿名统计开关会把登录卡撑长，登录这一步反而更难读。没有采纳。
- 默认同意，或者只在安装时展示说明：首次启动最少一步，但没有取得明示同意，隐私与上架要求上不成立，沿用 ADR-0077 的结论。没有采纳。
