# ADR-0005 崩溃与诊断上报改用自建 Sentry

## 状态

已取代，见 [ADR-0006](0006-诊断报告的采集范围.md)。

## 日期

2026-11-13

## 背景

现在的崩溃记录是 `filesDir` 里的一个 JSON 文件，只在本机保存最近几次未捕获错误与启动次数，不联网、不进数据包。团队要按 [03 第 4 节](../03-团队分工与协作.md) 观察内测的崩溃率，仅靠本机文件无法汇总，用户也无法主动把问题发回来。原先“诊断不联网”的口径已经确认去掉，学习记录仍然只保存在本机。

Sentry 可以自建，事件与堆栈留在自己的服务器上，适合不把学习数据交给第三方的要求。Flutter SDK 支持离线缓存、原生崩溃捕获与 release health，能满足“崩溃率低于 1%”的统计口径。

## 决定

用 `sentry_flutter` 10.4 接入自建 Sentry 实例。DSN 通过 `--dart-define=SENTRY_DSN` 注入，仓库不保存地址与密钥；构建时没有 DSN 就跳过初始化，PR 构建与本地调试不产生请求。

删除本机的崩溃 JSON 文件与 `CrashLog`，所有 `record` 调用改走一个 `Diagnostics` 门面：它把异常交给 Sentry，测试里换成空实现。启动计数与崩溃率用 Sentry 的 session 统计，不再本地记。

初始化放在 `runApp` 之前，关闭个人信息（`sendDefaultPii: false`）、截图与视图层级，`beforeSend` 去掉消息正文、`extra` 里的学习内容、SQL、绑定参数与本机路径，`beforeBreadcrumb` 去掉文本输入类面包屑；先只收错误与 session，`tracesSampleRate` 取 0，稳定后再开少量性能采样。

设置页增加“发送崩溃报告”开关。开发包默认开，正式包默认关、由用户主动打开；开关状态写在应用私有目录的小文件里，启动时先读取，关闭时不初始化 Sentry，也不产生网络请求。

## 代价与边界

- 自建 Sentry 需要一台服务器、域名、证书与升级维护，DSN 与访问权限由项目组管理。
- 诊断从本机变成远端，必须保证事件里不含学习正文、API Key、SQL 与路径；这靠 `beforeSend` 与测试保证，代码评审要把它当成隐私边界。
- SDK 增加原生依赖与安装包体积，首次启动多一次初始化；断网时事件进本地队列，恢复网络后上报。
- 上报范围先只覆盖错误与 session，不做性能追踪；需要定位卡顿时再单独评估采样率与数据量。
- 开关默认值在开发包与正式包不同，文档要写清；用户关闭后，崩溃率统计只覆盖同意上报的用户，报告里要注明样本边界。

## 替代方案

- 继续只写本机文件。没有采纳的原因是内测阶段无法汇总崩溃率，用户也无法把问题发回来。
- Firebase Crashlytics。没有采纳的原因是数据落在第三方云，和“自建、学习数据不外流”的要求冲突。
- Sentry 官方 SaaS。没有采纳的原因是项目要求自建；SaaS 的运维成本更低，但数据位置不符合要求。
