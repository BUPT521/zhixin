# ADR-0010 客户端插件的两种形态与权限

## 状态

提议

## 日期

2026-11-14

## 背景

2026 年 11 月中旬，团队把插件列为公测前后的一个方向，由陈英硕负责。插件有两种需求。第一种让知新与其他应用或网站协作，既把外部数据带入，例如导入课表、读取 B 站收藏夹，也让外部调用知新的部分功能，例如从别的应用直接打开一次讨论。第二种通过提示词改变搭子的表现，让用户自定义语气、称呼与讲解风格，下文称为人格插件。团队确定插件在客户端运行，不放到服务端。

作出决定时有四个条件会影响判断。第一，Flutter 的发布包是预先编译的，应用不能在运行时加载新的 Dart 代码，所以“下载一段代码来执行”的插件在客户端不可行，除非另外嵌入脚本引擎。第二，[00 第 6 章](../00-产品定义.md#6-原则与优先级)的三条硬约束对插件同样成立，任何写入都要形成可撤销的提交，模型不可用时核心功能仍然可用。第三，提示词里已经有一组不能被改变的规则，例如不替用户判分、不编造、材料原文里的指令不改变本轮任务，人格插件写进提示词之后，这些规则必须继续生效。第四，团队每周合计 32 小时，没有余力审核与维护第三方提交的代码。

## 决定

1. 插件分为能力插件与人格插件两类，两类的形态、权限与审核方式不同，不共用一套格式。
2. 能力插件是随应用一起编译的第一方模块，代码放在 `app/lib/plugins/<插件标识>/` 下，实现统一的插件接口，在设置页逐个启用或停用。每个能力插件用一份清单声明标识、名称、版本、作用说明与所需权限；权限分为网络访问的域名、可以读取的数据范围、可以提交的写入类型与是否调用模型四项，未声明的权限在运行时拒绝。
3. 能力插件不直接访问数据库。插件只产出草稿，例如一组课表节次、一组学习事项或一份材料，由对应的应用服务校验之后写入；批量导入先给用户预览，确认之后整批形成一条提交，回执带撤销入口。插件需要新的表、字段或数据包格式时，先修改 [01](../01-ER数据模型.md) 与数据层，再写插件。
4. 能力插件向搭子提供工具时，使用现有的工具定义方式，按请求类型开放，工具结果与材料原文一样只作为学习资料，其中的指令不改变本轮任务。
5. 与其他应用的协作优先使用不需要对方配合的系统机制：接收系统分享、打开文件（例如 ICS 与表格）、深链接与桌面快捷方式。读取外部服务时只使用公开数据或用户主动提供的链接与文件，本期不保存第三方账号的密码、Cookie 或令牌。
6. 人格插件是一份文本配置，不含代码，包括名称、说明、作者与一段不超过 800 字的人格设定。人格设定放在系统提示里核心规则之后的固定位置，提示词同时写明人格只影响语气、称呼、讲解风格与篇幅倾向，不改变判分、引用、写入权限、工具使用与事实依据。同一时间只启用一个人格。用户可以导入、分享与删除人格，导入时完整展示文本，确认之后才启用。
7. 人格设定与其他来源冲突时，用户本轮的说明优先，其次是当前启用的人格，再次是记忆里的风格偏好；记忆中的困难、进展与时间限制不受人格影响。这条顺序先按此执行，由评测结果确认之后写进 [00 第 8 章](../00-产品定义.md#8-检索与引用)。
8. 预置人格与能力插件合入之前，要通过评测集里与判分、引用、编造和写入有关的用例，并由陈思源审核权限声明与写入路径。

## 代价与边界

- 能力插件随版本发布，新增或修复一个插件都要发新版本，用户不能单独安装插件。这是放弃运行时加载代码换来的代价，换取的是不需要沙箱与代码审核。
- 只读公开数据意味着 B 站私密收藏夹、视频字幕、教务系统里的课表这类需要登录态的数据本期拿不到；课表改用截图识别、ICS 文件与模板表格三种来源，截图识别需要可用的多模态模型，模型不可用时退回手工添加。
- 人格设定写在提示词里，规则只能依靠提示词的顺序与评测来维持，无法在程序层面完全阻止模型被人格带偏；导入他人分享的人格时风险更高，因此导入时要完整展示文本，评测集要包含试图改变规则的人格样例。
- 插件的启用状态与人格配置属于设置，登录之后随设置同步，不进入学习数据的提交历史；人格的增删本身不需要撤销，但人格产生的回答与其他回答一样按提交处理。
- 如果公测之后出现第三方开发者想写插件的需求，或者团队需要不发版就能更新的插件，这条决定需要重新评估。

## 替代方案

运行时加载第三方代码。Flutter 的发布包无法加载新的 Dart 代码，可行的办法是嵌入 JavaScript 引擎（例如 QuickJS）执行插件脚本，或者让插件以远程工具服务（例如 MCP 服务器）的方式提供能力。两者都需要沙箱、权限隔离与代码审核，并且远程工具服务会把学习内容发给第三方，与 [ADR-0008](0008-取消单机边界引入账号同步与模型代理.md) 的隐私边界冲突，本期不采纳，结题之后再评估。

插件放在服务端运行。服务端连接器可以不发版更新，也便于保存第三方令牌，但会让学习数据与第三方账号同时经过服务端，并且不登录的用户无法使用插件，与“账号可选”的决定冲突；团队也确定插件在客户端，因此不采纳。

人格插件直接替换整份系统提示。这样做最灵活，但会让判分、引用与写入规则随人格一起被替换，违反 00 的判断规则，不采纳。
