# ADR-0050 客户端统一为知新服务

## 状态

已采纳。2026-11-22 决定。本条取代五处内容。第一处是 [ADR-0008](0008-取消单机边界引入账号同步与模型代理.md) 决定第 4 条中“用户仍可以在设置页填写自己的 key 直连提供方，此时请求不经过服务端”一句。第二处是 [ADR-0027](0027-服务端承担嵌入与检索.md) 决定第 4 条末尾“用户自带 key 直连仍然保留”一句。第三处是 [ADR-0029](0029-模型来源路由与嵌入代理.md) 代价与边界中“索引键在模型名前加 `server:`，与自填接口里同名的模型分开建索引”一句，这半句只对自填来源有意义。第四处是 [ADR-0030](0030-服务端不建检索索引.md) 决定第 3 条与影响表中“自填 key 直连”的列举，这两处随自填来源一起失效。第五处是 [ADR-0049](0049-嵌入统一走百炼与查询向量也走云端.md) 决定第 5 条与代价与边界中“自填 key 直连保留”的内容。前四条 ADR 的其余决定继续有效，服务端 [ADR-0029](0029-模型来源路由与嵌入代理.md) 的决定 1 至 7 与 [ADR-0035](0035-模型来源只保留后台配置.md) 的配置口径不受本条影响。[ADR-0009](0009-API后端采用Go与分层框架.md) 代价与边界中“选择‘知新服务’时接口风格固定为 Chat Completions”的写法改动一句，服务端只代理一种线格式的结论不变。

## 日期

2026-11-22

## 背景

[ADR-0008](0008-取消单机边界引入账号同步与模型代理.md) 引入模型代理时，把自填 key 直连保留为第二条路径，理由是不登录的用户仍然可以使用模型，用户也可以自己承担费用。此后模型入口逐步增加：聊天可以选“自填 Key”或“知新服务”，语义索引可以选“知新服务”、自填的 OpenAI 兼容嵌入接口或本机哈希，聊天还支持 Chat Completions、Responses 与 Anthropic Messages 三种线格式，自填入口另有接口地址、key 与连接测试。这些入口合起来有三类维护成本。

第一类是提示词与协议差异。不同提供方对思考模式、`max_tokens` 与工具调用的处理不同，提示词按一套协议调好之后，在另一种进入方式下回答质量会变，每次改提示词都要在多个入口上分别复核。

第二类是故障归因。用户报告“模型不回答”时，要先分清是应用、用户自己的 key 与地址，还是服务端与上游提供方的问题，排查看不到用户的 key，也看不到提供方的账单，定位时间大部分花在判断问题出在哪一层。

第三类是额度与隐私口径。用户自付额度时，可发送范围、费用与数据流向由用户自己决定，应用无法核对；这些口径与登录用户的托管额度、可发送范围和缓存规则并存，文档、页面与验收用例都要分别说明一遍。

团队四人每周合计 32 小时，选题、提示词、界面、验收与运维由同几个人分担，同时维护两条模型路径、三条嵌入路径和三种线格式的分摊成本无法承担。

服务端已经具备收口条件。来源与路由写在 `llm_provider`、`llm_model`、`llm_route` 三张表里，管理后台可以配置多个来源并设置优先级、权重与故障切换（[ADR-0029](0029-模型来源路由与嵌入代理.md)），环境变量来源已于 2026-11-20 去掉，配置只从后台读取（[ADR-0035](0035-模型来源只保留后台配置.md)）。聊天与嵌入都经同一个服务端转发，嵌入来源收成一个，查询向量同样走云端（[ADR-0049](0049-嵌入统一走百炼与查询向量也走云端.md)）。换上游、换模型、调额度都已经可以在后台完成，不需要用户改动设置。

## 决定

1. 客户端的模型入口只有“知新服务”一种，即 zhixin-api 的模型代理。聊天与嵌入都经这个入口转发；客户端不再提供“自填 Key 直连提供方”，也不再有接口风格、接口地址、API Key 与自填嵌入接口这四项用户配置。

2. 出厂默认服务地址是 `https://zhixin.chensiyuan.work`，指向项目组部署的第一套实例。用户在账号页可以把服务地址改成自建实例，改的是同一个入口指向哪一台服务器，不改变“只有一种模型来源”。自建实例的管理员按 [server/README](../../server/README.md#模型代理) 配置自己的来源、模型与额度。

3. 登录之后以访问令牌代替 key。客户端只在服务地址后面拼出 `/v1/llm` 作为模型接口地址，访问令牌过期时先刷新再重试；未登录或登录失效时不发出模型请求。

4. 不登录完全不能使用模型，只能退回本地兜底。本地兜底与 [00 第 6 章](../00-产品定义.md#6-原则与优先级)第 3 条硬约束原本规定的行为一致：已有记录仍可查看，结果仍可记录，下一步建议由本机规则给出。本条收窄的是模型调用，三条硬约束不变。

5. 语义索引的嵌入来源只剩两项，即“知新服务”与“本机哈希（不联网）”。本机哈希对每个片段计算词项哈希向量，不调用模型也不联网，只用于断网、未登录时的降级检索；自填的 OpenAI 兼容嵌入接口删除。登录之后自动同步开启时，索引刷新按 [ADR-0030](0030-服务端不建检索索引.md) 先取服务端缓存再补算（[ADR-0049](0049-嵌入统一走百炼与查询向量也走云端.md)）。

6. 服务端 zhixin-api 不改。`llm_provider`、`llm_model`、`llm_route` 三张配置表、管理后台的多来源配置、优先级与故障切换都保持原样。文档中的“官方”与“知新服务”指客户端看到的入口，“后台上游来源”指管理员在后台配置的提供方，两者不是一回事：用户界面只出现前者，后台来源只在管理页面出现，由管理员维护，用户不可选择。

7. 用户不能绕开服务端直连上游提供方。客户端界面与设置项里不再出现提供方地址、key 与线格式的配置，用户改用其他服务时要换服务地址或联系管理员。

8. 付费与额度只由项目组承担。项目仍不收费，不设订阅与内购；模型费用由捐赠与学院经费承担，额度按 [ADR-0036](0036-实例模型预算与账号用量分开.md) 的实例预算与账号用量口径在服务端控制；个别账号需要更高的额度时，由管理员在后台单独调整。

9. 上游提供方更换模型或更换提供方由管理员在后台完成，客户端不需要发版，用户不受影响。

## 代价与边界

- 不登录的用户完全无法使用模型。内测与公测的用户大多不熟悉模型服务，未登录时只能得到本地兜底给出的步骤，本地建议覆盖的范围小于模型回答。首次使用引导要把登录放在第一步，引导错位会直接影响首日留存。

- 单一入口意味着服务端不可用时所有用户的模型请求一起停顿，客户端只有本地兜底这一条退路，没有第二条路径可以切换。

- 用户自行承担额度、自行选择提供方的灵活性消失。希望使用其他提供方的用户只能联系管理员，或者自行部署 zhixin-api 并把服务地址指向自建实例；后者要求用户具备部署与配置能力，远远超出普通用户的范围。

- 费用全部落在项目组的经费上，额度用完或经费不足时没有用户自行承担费用的路径。额度用尽只由管理员调高，用量监控与额度调整成为运维的固定工作。

- 用户不再掌握自己请求发往哪一家提供方，可发送范围只能按账号设置。隐私口径因此集中在服务端一份文档里，与社会公开说明一致；如果以后需要按用户选择发送范围，这一条要重新评估。

- 服务端仍然承担上游来源的运维，后台配置错误、key 失效与上游故障都由管理员处理。用户报告的“模型不回答”由管理员结合后台用量与日志定位，客户端只说明失败类型，看不到上游的具体原因。

- 客户端代码里的自填配置、接口地址与 key 存取、自填嵌入客户端与线格式选择要一并删除，按 [ADR-0001](0001-开发阶段不向下兼容.md)，设置键与本地配置直接删除，不写迁移（[ADR-0002](0002-本地数据不做迁移.md)）。删除之后，此前填过自填入口的用户升级时会退回“只支持知新服务”的界面，需要登录才能继续使用模型。

- 重新评估的条件有三项：内测反馈显示未登录用户的比例高到影响留存，或者服务端可用性长期不足，或者学院要求用户自行承担费用。任一项出现时再讨论是否恢复第二条入口。

## 替代方案

- 保留自填 key 直连。它能让不登录或不愿登录的用户继续使用模型，也能让用户自行承担费用。没有采纳的原因在背景一节：两条路径的分歧落在提示词协议、故障归因与额度隐私三处，团队没有余量同时维护；用户自填的 key 与地址不在应用的控制范围内，出现问题时无法核对。

- 聊天统一走知新服务，嵌入保留自填接口。聊天是用户最常用的入口，嵌入是低频的后台步骤，看起来可以分开处理。没有采纳的原因有两个：自填嵌入接口与知新服务的嵌入来源要在索引键上区分，稍有不慎两个来源的向量会混进同一份 collection，排序会悄悄错乱而不报错（[ADR-0049](0049-嵌入统一走百炼与查询向量也走云端.md) 代价与边界）；设置页上的自填表单、连接测试与凭据存取也会继续保留，收口的效果减半。

- 把服务端也收成单一上游，后台只配一个来源。这样做可以让“来源”这个概念彻底消失。没有采纳的原因是三张配置表与后台已经实现并且在线运行，多来源与故障切换在上游故障时能够自动换用；再收一次需要改服务端代码、表结构与运维手册，换来的只是文档上少一层概念，而用户本来就看不到后台来源。
