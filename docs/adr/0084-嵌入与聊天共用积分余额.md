# ADR-0084 嵌入与聊天共用积分余额

- 状态：已采纳，补充 [ADR-0067](0067-聊天额度改走即刻收积分包.md)、[ADR-0068](0068-聊天积分包的档位与价格.md)、[ADR-0069](0069-积分余额的本地副本与预留放行.md)、[ADR-0070](0070-额度预留与失败结算口径.md)、[ADR-0071](0071-核销只读已结算用量与额度用完的原因.md) 与 [ADR-0076](0076-管理后台按密钥的对账视图.md) 的积分适用范围
- 日期：2026-11-27

## 背景

聊天和嵌入都由知新服务代理，但嵌入用完每日免费额度后会拒绝请求，即使账号还有已购积分，材料索引和语义检索也只能等次日恢复。[阿里云百炼实时推理价目](https://help.aliyun.com/zh/model-studio/text-embedding-v4)列出中国内地 `text-embedding-v4` 的输入单价为每百万 token 0.50 元，按约 1.2 倍计算的目标价为 0.60 元。

## 决定

每个嵌入输入 token 记一个计费 token，按现行默认的每积分一万个计费 token 折算，每百万输入 token 需要 100 分，以萤火档的积分单价计为 0.60 元。灯火和星河档有购分折扣，同样的用量分别折合约 0.56 元和 0.53 元。模型价目作为折算依据，向量仍由实例配置的模型生成。

聊天和嵌入先分别使用各自的每日免费额度，按账号汇总两项超额量后共用积分余额。服务端预留额度和显示可用余额时计入在途请求，结算时只合计当天已结算的超额量，统一向上折成整积分并核销尚未申请的差额。向量缓存的查找不产生模型用量，实例预算继续只计入免费用量。

## 代价与边界

两种用途都可以占用同一余额，资料导入和索引重建产生的超额嵌入用量也会减少可用于聊天的积分。账本按自然日汇总，服务端在实例自然日切换后启用新规则，使首个计费日的用量按同一规则产生。表结构、计费 token 单位和已购积分的折算比例沿用现有定义，无需迁移。

## 替代方案

为嵌入单独出售积分会增加一套余额、购买和核销流程。共用既有余额可以在任一用途用完免费额度后继续使用，账号页仍分别列出两项免费额度，便于用户核对。

## 影响

产品口径见 [00 第 7 章](../00-产品定义.md#7-边界)，账号页与购买页见 [02 第 3.16 节](../02-产品与交互.md#316-账号与云同步)，上线核对见 [运维手册第 4.11 节](../../server/运维手册.md#411-即刻收积分包的上线与回滚)。管理后台的密钥用量按两种用途的计费 token 合计折算参考积分，实际扣除的积分以账号核销流水为准。
