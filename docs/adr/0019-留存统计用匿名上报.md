# ADR-0019 留存统计用匿名上报

## 状态

已采纳。服务端的接收端点、按日统计表与 180 天清理已于 2026-11-18 实施，见 [server/README](../../server/README.md#留存统计)；客户端的上报任务、安装标识保存、首次使用说明与设置开关待实施。

## 日期

2026-11-15

## 背景

03 第 4 节的 S4、S5 要求统计一周与四周留存。现在应用不上报任何使用数据，账号也还没有上线，留存没有数据来源（04 第 5 节 D3）。登录用户可以在服务端按请求日期推算活跃，不登录的用户占多数，只统计登录用户会让样本偏向早期愿意注册的人。采集又不能碰学习内容，也不该把用户变成可追踪的对象。

## 决定

1. 不登录的用户每天最多上报一次，内容包括随机安装标识、日期、应用版本与平台，不含题目、材料、消息、记忆或任何正文。
2. 随机安装标识在首次启动时生成并保存在应用私有目录，卸载或清空数据后重新生成，不与账号、设备编号、IP 或广告标识关联。
3. 默认开启。首次使用时用一次说明讲清采集内容与用途，设置页提供关闭入口；关闭之后不再上报，已经上报的记录保留。
4. 服务端按日保存安装标识的哈希与日期，用于计算活跃天数；不保存原始标识，按 180 天滚动删除。
5. 登录用户的活跃按服务端收到的请求日期统计，不额外上报。
6. 上报在启动之后的空闲任务里发出，失败静默重试一次，不阻塞首屏，只写本机诊断记录。

## 代价与边界

- 随机标识仍是长期存在的个体标识，虽然不含学习内容，极端情况下可以用来区分设备；哈希与滚动删除缩小这个风险，但做不到零。
- 关闭入口在设置页较深的位置，实际关闭比例可能很低，留存数字会偏向保留默认设置的用户。
- 服务端要新增接收端点、一张按日统计表与删除策略，增加一点存储与运维成本。
- 只统计活跃，不统计功能使用；要统计功能需要另一次决定。

## 替代方案

- 只统计登录用户：样本偏，内测早期登录比例低；未采纳。
- 完全不采集，用试用回访代替：S4、S5 无法按指标判定；未采纳。
- 接入第三方统计 SDK：引入外部依赖与隐私条款，数据还会送到第三方；未采纳。
- 用设备编号或 IP 去重：可追踪性更强；未采纳。
