# ADR-0034 模型路由用量汇总

## 状态

已采纳。本条补充 [ADR-0029](0029-模型来源路由与嵌入代理.md) 的路由管理与 [ADR-0031](0031-云端写入与托管模型的资源预算.md) 的结算口径。

## 日期

2026-11-19

## 背景

账号额度只按自然日与用途结算，管理员遇到托管用量增长或来源故障时，无法据此判断哪个模型或来源承接了请求，也无法区分上游实报与预留估算的用量。

## 决定

每次托管路由尝试结束时，按自然日、用途、对外模型、来源编号和来源侧模型名汇总次数与 Token。每次请求实际执行的第一条路由计入“首次尝试”，此前已有尝试失败时，随后实际执行的每一条路由各计一次“故障切换”。嵌入拆批按一次路由尝试计数，管理后台测试、缓存查找与请求发出前的拒绝均不计入。路由汇总只保留这些维度和计数，因此可以保留停用路由的历史，也不会因为某个账号注销而改变过去的实例用量。汇总与账号额度分别写入，管理后台用汇总观察来源表现，转发仍根据账号额度和实例预算决定是否放行。

聊天代理对已发出的尝试结算可读取的上游用量，缺少用量时保留预留值。报表只将完整回答计为成功，并在未成功次数下列出达到输出上限和客户端中断的次数，健康状态按 [ADR-0059](0059-模型路由按故障范围切换与恢复.md) 更新。

看板查询同时返回每条路由在区间内的总量与有记录日期的用量，管理员切换模型、来源或日期时，浏览器可以使用同一次查询的结果重算趋势和明细，所需数据来自现有日汇总表。

2026-11-26 在汇总里增加缓存命中与上报覆盖两组数字，都按首次尝试与故障切换分列。命中量来自 Responses 的 `usage.input_tokens_details.cached_tokens`，只有响应里带了 `cached_tokens` 才算一条缓存上报：字段存在而值为 0 表示这次确实没有命中，字段缺失表示这次拿不到命中数据，两种情形分开计数。区分之后，后台因此能分开看“路由确实没命中”与“来源没有返回缓存字段”；合在一起时缺报按零命中进入占比，命中率因此偏低，据此调整路由权重就会调错。两组数字只用于观察，不参与额度与积分结算，折算口径仍是 [ADR-0066](0066-额度按缓存命中折算.md)。

## 代价与边界

每次尝试多写一次日汇总，写入失败时记录服务日志，账号额度和路由转发仍可执行。查询结果随区间内有记录的路由和日期增加，单次查询最长覆盖 30 天。一次客户端请求可能尝试多条路由，所以看板上的成功率衡量路由尝试，费用核对仍使用提供方账单。

缓存统计给汇总表增加八列，每次尝试仍然只写一行；已有的库按 [ADR-0057](0057-服务端改表清空重建.md) 重建，不写迁移。上报条数依赖来源在响应里给出 `input_tokens_details`，来源不返回这个对象时只能看到缺报，无法反推真实的命中情况，因此命中率要连同覆盖率一起看，覆盖率过低的时段不适合用来比较路由。

## 替代方案

沿用账号每日额度可以显示已有的总用量，但无法回答哪条路由承担了调用。逐请求保留明细便于追踪单笔调用，但会增加存储量和账号关联信息，因此采用日汇总。
