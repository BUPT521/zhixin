# ADR-0034 模型路由用量汇总

## 状态

已采纳。本条补充 [ADR-0029](0029-模型来源路由与嵌入代理.md) 的路由管理与 [ADR-0031](0031-云端写入与托管模型的资源预算.md) 的结算口径。

## 日期

2026-11-19

## 背景

账号额度只按自然日与用途结算，管理员遇到托管用量增长或来源故障时，无法据此判断哪个模型或来源承接了请求，也无法区分上游实报与预留估算的用量。

## 决定

每次托管路由尝试结束时，按自然日、用途、对外模型、来源编号和来源侧模型名汇总次数与 Token。路由汇总只保留这些维度和计数，因此可以保留停用路由的历史，也不会因为某个账号注销而改变过去的实例用量。汇总与账号额度分别写入，管理后台用汇总观察来源表现，转发仍根据账号额度和实例预算决定是否放行。

聊天代理在写出响应前核对上游响应，遇到无效的非流式响应或明确返回 JSON、HTML 的流式响应时，按原有候选次序尝试下一条路由。流式响应已经开始时，服务端依据结束标记或正常收尾的 `finish_reason` 判断路由是否完成，提前中断会表现为未成功，客户端主动中断则不影响来源健康状态。

## 代价与边界

每次尝试多写一次日汇总，写入失败时记录服务日志，账号额度和路由转发仍可执行。一次客户端请求可能尝试多条路由，所以看板上的成功率衡量路由尝试，费用核对仍使用提供方账单。

## 替代方案

沿用账号每日额度可以显示已有的总用量，但无法回答哪条路由承担了调用。逐请求保留明细便于追踪单笔调用，但会增加存储量和账号关联信息，因此采用日汇总。
