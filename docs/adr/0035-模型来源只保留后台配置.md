# ADR-0035 模型来源只保留后台配置

## 状态

已采纳。本条取代 [ADR-0029](0029-模型来源路由与嵌入代理.md) 决定第 2 条中保留环境变量只读来源 `env` 的部分；路由、嵌入代理、额度与管理后台本身不变。

## 日期

2026-11-20

## 背景

[ADR-0029](0029-模型来源路由与嵌入代理.md) 把环境变量里的那一组配置保留为只读来源 `env`，理由是后台需要数据库、管理令牌与 `ZHIXIN_SECRET_KEY`，而部署流水线只换可执行文件，这样第一套实例升级当天不进后台也能继续服务。

后台启用之后，`env` 带来的是两套配置。后台的来源列表里有一个看得见、改不了、也不能被路由引用的来源；新增模型的前提是“后台来源至少一个”，提示因此和列表矛盾；key 有两处轮换方式，模型清单有两处维护位置，同名模型还有后台覆盖环境变量的规则。2026-11-20 管理员在第一套实例的后台点“新增模型”，被提示“先新增至少一个来源”，而来源列表里明确有一个只读来源，这个问题由此暴露。管理后台当时已经启用，数据库、管理令牌与加密密钥都已就位，`env` 原本要保住的升级通道不再承担作用。

## 决定

1. 运行期只有一个配置入口：管理后台写入的 `llm_provider`、`llm_model`、`llm_route`。路由快照只从这三张表读取。
2. 去掉 `env` 来源：`ZHIXIN_LLM_BASE_URL`、`ZHIXIN_LLM_API_KEY`、`ZHIXIN_LLM_MODELS` 与 `ZHIXIN_LLM_EMBEDDING_MODELS` 不再读取；`env` 从保留名与接口的 `source` 枚举中删除，`llm_provider.id` 的约束只剩小写字母、数字、`-` 与 `_`。
3. 启用后台、数据库或收款的实例只有在至少一个模型可以路由、所有来源密钥均可解密时才正常启动。首次配置或修复密钥时，用 `zhixin-api configure-models` 启动仅监听本机的管理模式，退出后再正常启动。

## 代价与边界

- 换 key 与增删模型都在后台完成，后台只经 SSH 隧道访问。key 需要轮换时，管理员要在隧道里编辑来源，`api.env` 不再提供改文件重启的应急路径。
- 数据库为空时要先在管理模式中录入模型，重建库时也可以恢复模型配置表。因为管理模式只提供管理页面与接口，账号、同步、备份与反馈随正常服务一起恢复。
- `ZHIXIN_SECRET_KEY` 的重要性上升：它丢失或更换之后，已保存的 key 全部无法解密，需要重新填写。
- 三张配置表不进入整库备份与数据包，重建实例时按[运维手册](../../server/运维手册.md#3-配置)重新配置一遍。

## 替代方案

- 保留两套并允许后台路由引用 `env`：提示矛盾消失，但两套配置、两处 key 轮换与同名覆盖规则都要继续维护。
- `env` 只在表为空时导入一次：运行期只有后台一套，新实例第一次启动仍有模型；代价是多一个只执行一次的开关，管理员容易误以为环境变量继续生效。第一套实例已经有后台，暂时不需要这条路。
- 只留 `env`：回到 ADR-0029 之前，多来源、故障切换与嵌入接第二家都没有了。

## 影响

- 服务端代码：`server/internal/llmproxy`（路由快照与管理接口）、`server/internal/config`、`server/internal/admin/ui`、`server/internal/store/schema.sql`。
- 接口：[openapi.yaml](../../server/api/openapi.yaml) 的 `AdminProvider` 与 `AdminModel` 去掉 `source`，生成文件随之更新；`/v1/llm/models` 与客户端不受影响。
