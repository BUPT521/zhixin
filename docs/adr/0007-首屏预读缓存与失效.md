# ADR-0007 首屏预读缓存与失效

## 状态

提议

## 日期

2026-11-14

## 背景

L6 计划在首页首屏稳定后预读“学习记录”和“安排”，目前服务按需查询数据库。`dataVersion` 用于通知页面重新读取，覆盖恢复、清空、导入、撤销和每日截止小时变化，普通的新增、编辑和删除则走 `GuardedDatabase` 的独立写入或命令事务，因此只核对 `dataVersion` 会让日常写入之后的预读结果继续命中。

## 决定

记录首屏服务与安排服务各保留一份预读结果，预读与页面首读共用同一个查询入口和结果类型。“学习记录”预读默认筛选的第一页，参数包括筛选、页长和偏移量，结果包含每条记录对应的题目和最近一次作答的判断。“安排”预读当前自然周，以周起始日区分查询，结果最迟在跨周或所读的下一次预约到达结束时间时失效，因为 `loadWeek` 会按读取时的当前时间选择尚未结束的预约。

缓存同时核对 `dataVersion` 与进程内的数据库提交序号。`GuardedDatabase` 在 SQLite 确认外层事务提交后、释放 `DatabaseGate` 的独占访问前推进序号，单条写入和多表命令共用这个位置。事务回滚、请求去重命中和没有业务净变化的命令维持原序号。恢复、清空、导入、撤销以及影响安排回执的历史清理使用原有独占区，在数据或历史提交后先使相关缓存失效，再做可能失败的附件缓存重建等后续工作。每日截止小时调整仍使用 `dataVersion`，服务同时核对当前时间口径。

按版本号判断失效的部分在页面改用流式查询之后由 drift 的通知接管，见 [ADR-0014](0014-流式查询与版本通知.md)；本条关于首屏两份预读结果的其余要求不变。

缓存命中、首屏组合查询和结果发布在同一个共享访问范围内完成，保证各子查询来自同一份已提交数据。预读和页面在取得共享访问后按查询参数与版本合并在途请求，读取失败后移除在途项，页面可以重新查询。页面等待过渡结束后重新取得共享访问，在同一个同步回调内核对版本、参数与有效期并回填，任一条件变化时退出共享区后按当前条件重读。事务内查询直接读取事务视图，缓存只供事务外读取使用。

## 代价与边界

首版每次有净变化的业务提交同时失效两栏缓存，频繁保存草稿也可能使预读结果作废。首屏的多次查询共用一个共享访问范围，写入需要等已经进入的读取结束，因为 `DatabaseGate` 会优先放行已经排队的独占请求，所以新的预读不能插到它前面。真机 profile 若确认首次切栏仍有明显等待，再实施和度量这项改动。

## 替代方案

沿用 `dataVersion` 作为唯一键会漏掉普通写入。让每个写入页面自行清理缓存，容易遗漏直接调用仓库的入口以及一笔事务对题目、目标、事项和回执的联动更新。提交后统一推进序号的代价是失效范围较大，适合只保留两份首屏结果的规模。

## 影响

实现入口见 [L6](../动画流畅性优化方案.md#8-补充界面加载本身的优化点)、[`GuardedDatabase`](../../app/lib/data/db/guarded_database.dart)、[整库操作](../../app/lib/app_scope_data.dart)与[版本服务](../../app/lib/data/revisions/revision_service.dart)。实现时验证单条写入、事务回滚、去重、恢复或清空期间的在途读取、切栏动画期间的写入，以及跨周和预约到期后的缓存命中情况。
