# ADR-0076 管理后台按密钥的对账视图

## 状态

已采纳（2026-11-25，服务端同日实施）。

## 日期

2026-11-25

参考积分按聊天与嵌入计费量合计折算见 [ADR-0084](0084-聊天与嵌入共用积分.md)。

## 背景

接入密钥从 2026-11-24 起可以签发（[ADR-0063](0063-模型代理接入密钥.md)），每把密钥与账号共用每日额度与积分，`llm_usage` 已经按 `api_key_id` 分开记用量。密钥是访问令牌之外唯一能长期调用模型的凭据，用户把它交给脚本或第三方工具之后，泄漏与超额使用都要按密钥定位。

后台此前只有 `/admin/v1/usage` 的路由维度汇总：它说明哪个模型、哪条来源用了多少，不说明哪把密钥用了多少、折算成多少积分、还有多少预留没有结算。积分开售之后（[ADR-0067](0067-聊天额度改走即刻收积分包.md)、[ADR-0068](0068-聊天积分包的档位与价格.md)），对账要同时查看计费 token、核销积分与即刻收余额，[计量与计费审查](../计量与计费审查.md)第 4.3 条已经指出后台看不到计费量。没有这个视图时，运维只能自己写 SQL 语句查询 `llm_usage`，每次都要重写一遍，也看不出在途预留与缓存命中。

## 决定

1. 新增只读接口 `GET /admin/v1/key-usage?days=N`，`days` 允许 1 至 30、默认 7，包含今天，按服务端时区（`ZHIXIN_TIMEZONE`）计算。响应给出区间内每把密钥的已结算计费 token、在途预留、上游报告的输入量与其中命中缓存的部分，对话与嵌入分开，另带按自然日的同样明细、名字、前缀、撤销状态与最近使用时间。访问令牌发起的调用记在 `key_id` 为空字符串的一行，账号合计因此能对上。
2. 数据只从 `llm_usage` 与 `api_key` 读取，不新增表与列。`llm_usage.api_key_id` 不是外键，密钥撤销超过保留期之后行由每日清理删除，所以查询用左连接：匹配不到时名字与前缀为空，用量行本身保留。行是否还在单独给一个 `key_present`：名字为空的密钥与已被清理的密钥都不带名字，撤销状态也只在行还在时才为真，只看这两项会把已清理的密钥显示成“在用”，所以页面按 `key_present` 判断，行不在时显示“已清理的密钥”，名字为空但在用时用前缀辨认。
3. 响应只给每积分覆盖的计费 token 数（`tokens_per_point`，与核销同一配置），金额由页面按对话的计费 token 折算，向上取整，与核销的取整方向一致，不扣当天的免费额度，只作对账参考。嵌入不参与积分核销，单独列出，不折进积分，避免让人以为嵌入也能用积分支付；缓存命中率只看对话，嵌入的输入没有缓存语义，混进分母会把比例压低。
4. 这条视图不改变额度判定、预留、结算、核销与失败结算的任何口径，也不改变 [ADR-0063](0063-模型代理接入密钥.md) 决定第 4 条“密钥与账号共用额度、不单独定额度”的结论。后台在“密钥用量”页提供独立的统计范围与日期筛选，账号详情以完整账号编号进入该页的筛选结果。
5. 权限沿用管理令牌：接口在 `/admin/v1/` 下，与其余管理接口同一道中间件，不向普通账号开放。

## 代价与边界

按密钥折算的积分是估算值，不是实际核销。核销按账号当天合计的收费量申请，同一账号的多把密钥共用同一天免费额度，拆到每把密钥只能按计费 token 分摊；接口不承担这个分摊，页面也不承诺两者相等。核对实际收款仍要看账号的积分流水与即刻收余额。

视图是读取时的快照，请求在途期间预留尚未结算，同一天刷新两次数字可能变化。内存实现只合计已结算与在途预留，缓存命中与密钥名字为空，只有 PostgreSQL 给出完整字段；本地联调看到的趋势与总量仍然与额度判定一致。

接口一次最多返回 30 天，按密钥合并之后每把密钥带一个日明细映射，没有分页；当前的公测规模足够，账号与密钥继续增长之后需要分页或改成按账号查询，届时另开一条决定。密钥清理之后名字丢失，只能按密钥编号回查，这与 [ADR-0063](0063-模型代理接入密钥.md) 的保留期一致。页面显示账号编号，不显示邮箱，管理员需要联系用户时按编号查询。

## 替代方案

在 `/admin/v1/usage` 的响应里加一段密钥汇总。没有采纳的原因是路由统计不带账号维度，两者混在一个响应里会让契约与页面都变复杂；分开之后内存模式缺少密钥名字时只关掉这一块，路由用量照常可用。

让运维直接查询 `llm_usage`。没有采纳为界面方案的原因是每次都要重写 SQL 语句，容易看错列，也看不出在途预留与缓存命中；[运维手册](../../server/运维手册.md)保留查询语句，作为接口之外的手工兜底。

给每把密钥单独定额度与单价、由密钥自己的余额扣费。没有采纳的原因是这是产品口径的变化，[ADR-0063](0063-模型代理接入密钥.md) 已经明确密钥与账号共用额度，修改它要同时修改额度、核销与购买流程，超出“在后台补一个按密钥的计费视图”的范围；以后要做时另开一条 ADR。
