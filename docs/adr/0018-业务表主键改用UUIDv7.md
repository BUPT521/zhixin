# ADR-0018 业务表主键改用 UUIDv7

## 状态

已采纳。2026-11-15 定下形态，2026-11-16 实施完成：13 张业务表的主键与外键改为 UUIDv7 文本，schema 升到 27，版本引擎、仓库、域模型、界面与测试同步改用文本标识，旧库按 [ADR-0017](0017-表结构变化仍清空数据.md) 清空重建。

## 日期

2026-11-15（实施结果补记于 2026-11-16）

## 背景

业务表现在用 `INTEGER PRIMARY KEY AUTOINCREMENT`，14 张登记进版本采集的表里除 `profile` 固定为 1 之外都是自增整数。增量同步要让两台设备写入的行不冲突，自增整数满足不了；ADR-0008 的同步协议按提交序列传输净变化，主键必须在所有设备上唯一，并且撤销、恢复与版本明细都要按它定位。评估第 3.4 节比较过四种做法，D2 在 2026-11-15 定下采用 UUIDv7。

## 决定

1. 业务表主键改为 UUIDv7 文本，36 位小写、带连字符的规范形式，由客户端在写入时生成，不再使用自增整数。
2. 外键列、`revision_change.row_key`、撤销与恢复的定位、检查点投影、两类数据包与恢复校验、域模型、应用服务、界面状态与测试一并改为文本标识；`row_key` 直接保存目标表的主键文本。
3. 版本采集触发器与业务表主键一起改，schema 版本加 1，旧库按 [ADR-0017](0017-表结构变化仍清空数据.md) 清空重建，不写迁移。
4. 服务端的账号、会话、提交序列与备份编号由服务端生成，不参与客户端行标识，保持现有的 16 字节随机十六进制串，不随本次改造更换；同步载荷不解析主键，服务端只把 `ClientSchemaVersion` 加 1。
5. 改造顺序是 01 与 `schema.dart`、`tables.dart` 先行，再改版本引擎与仓库，最后改界面与测试；每一段单独提交，`main` 始终保持可构建。

## 实施结果

| 层 | 现行做法 |
|---|---|
| 表结构 | 13 张业务表的主键与外键改为 UUIDv7 文本，`profile` 保持固定为 1，`app_meta` 仍是不参与版本采集的设置表；schema 升到 27，旧库打开时按 [ADR-0017](0017-表结构变化仍清空数据.md) 清空重建 |
| 主键生成 | 客户端新增 `app/lib/domain/rules/uuid_v7.dart`，写入前生成 36 位小写文本：前 48 位是毫秒时间戳，同一毫秒内用 12 位序号递增，其余位取安全随机数，时间回拨时沿用上一次的时间戳 |
| 版本与数据包 | 采集触发器把目标表的主键文本记入 `revision_change.row_key`，撤销、恢复、检查点投影、两类数据包与恢复校验都按文本定位；提交、检查点与恢复点的编号仍是整数，旧数据包与旧版本库备份在恢复入口拒绝 |
| 索引 | 关键词索引（FTS5）改按业务表的隐式 `rowid` 关联，主键换成文本之后索引维护不变 |
| 仓库与界面 | 仓库在插入前生成主键并返回，域模型、应用服务、AI 工具、证据来源标识、页面状态、导航参数与测试的标识改为 `String`；页码、序号、分钟、限流参数与各类编号仍是整数 |
| 服务端 | 账号、会话、提交序列与备份编号仍由服务端生成 16 字节随机十六进制串；同步载荷不解析主键，`ClientSchemaVersion` 加 1 |

改造分表结构与版本引擎、仓库与域模型、界面与测试三段提交，在分支上验证后一起合入 `main`；生成代码重新生成过，与 `.drift` 文件一致。

## 代价与边界

- 主键从 8 字节整数变成 36 字节文本，业务行与索引体积上升，本地库与数据包略大；十万行量级可以接受，再大时看是否改二进制形式。
- 全部仓库方法、域模型以及大量界面与测试的签名要改，改动面是这几批里最大的，期间不能与别的结构改动并行，避免冲突。
- UUIDv7 依赖时间前缀，设备时钟明显回拨时新行会排到旧行之前；业务排序仍按各表的时间列，时间前缀只用于索引与导出，不影响判定。
- 旧库、旧测试库与旧备份全部失效，按 ADR-0017 清空；内测用户会看到一次重新开始。

## 替代方案

- 自增主键加设备前缀：实现最简单，但同步时要合并两个自增空间，主键长度不固定，撤销与恢复的定位规则也要跟着改；未采纳。
- 随机 UUIDv4：全局唯一，但随机顺序会让索引与按主键排序分散；未采纳。
- ULID：与 UUIDv7 相近，生态支持少，服务端已用 `google/uuid` 的 v7；未采纳。
- 复合键（设备编号加本地自增）：主键变成两列，外键、版本明细与数据包都要跟着改；未采纳。
