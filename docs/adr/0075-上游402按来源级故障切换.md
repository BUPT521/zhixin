# ADR-0075 上游 402 按来源级故障切换

## 状态

已采纳（2026-11-25，服务端同日实施，运维手册同步更新）。

## 日期

2026-11-25

## 背景

`deepseek-flash` 的三条路由里，OpenCode 排在优先级 0。它的来源地址写的是 `https://opencode.ai/inference/openai/v1`，这是按量付费的 Console 通道，余额为 0 时上游回 402 并说明 `OpenCode Go covers only requests to the OpenCode Go provider`，而项目组订阅的 Go 额度只在 `https://opencode.ai/inference/go` 这条通道生效。代理原来的重试判定只认 401、403、408、429 与 5xx，402 不在其中，于是整次请求停在这条路由上，后面两条本来可用的路由一次都没有被尝试，客户端看到的是模型调用失败，后台自测的返回是 `{"ok":false,"provider_id":"opencode","status":402}`。

## 决定

1. 402 与 401 同按来源级故障处理：跳过这个来源在同一次请求里的剩余候选，给来源记一次健康失败，连续三次之后按 [ADR-0059](0059-模型路由按故障范围切换与恢复.md) 的规则冷却，再由一次试探恢复。欠费的判定对象是凭据背后的账户，同一来源的其他模型会一起失败，换到同来源的下一条候选只会浪费尝试名额。
2. 402 计入“换下一个来源再试”的状态码集合，其余候选仍按优先级继续尝试；成功换源时客户端拿不到 402，只有全部候选都失败时，把最后一个来源的 402 转成问题响应返回。
3. 402 的故障原因写进管理端模型测试与健康状态（`HTTP 402`），后台据此能直接看到是哪一条路由欠费。

## 代价与边界

少数网关按模型计费，402 只针对单个模型；这类来源里仍然可用的其他路由会被一起跳过，直到试探恢复。代价可以接受，因为 402 在多数情况下意味着账户余额或额度出了问题，同来源其余路由继续尝试的收益很小。若某个来源改成按模型分别计费并成为常态，需要把 402 拆成按模型判定，另开一条 ADR 收窄本条。402 不消耗模型额度，也不产生计费用量。

## 替代方案

- 只把 402 加进重试集合、按路由级故障处理：会拿下一条同来源候选再撞一次 402，浪费尝试名额，后台也看不出来源欠费。没有采纳。
- 在后台关掉欠费的路由：一次性的处置动作，任何来源欠费都会复发，而且依赖人去发现。没有采纳为代码方案，作为临时处置手段保留。
- 更换上游账户或充值：属于运营动作，不改变代理遇到 402 时的行为，不能代替本条。没有采纳为代码方案。
