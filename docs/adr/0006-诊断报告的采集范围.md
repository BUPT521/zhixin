# ADR-0006 诊断报告的采集范围

## 状态

已采纳，取代 [ADR-0005](0005-崩溃与诊断上报改用自建sentry.md)。

## 日期

2026-11-14

## 背景

接入自建 Sentry 后，应用仍用本机 JSON 记录排障；Sentry 的 Flutter 集成也会独立捕获未处理的异常，因此只处理应用主动记录的异常，无法限制 SDK 自动捕获事件的内容。Drift 使用的 SQLite 异常还会将语句和参数直接拼入异常文本，按旧的错误格式替换字符串无法覆盖该输出。

## 决定

保留本机诊断文件、自建 Sentry、构建参数 `SENTRY_DSN` 与启动时的上报开关，具体行为见 [02 第 3.12 节](../02-产品与交互.md#312-外观)。主动记录和自动捕获的 Dart 异常经过同一个 `beforeSend`，新事件仅使用错误类型、程序定义的分类、SQLite 数字错误码、代码位置和发版信息；应用以结构化字段生成事件，因此发行版和错误位置仍可用于归类。

Android 由 Dart 读取开关后初始化 SDK，并保留会话计数；Java、ANR 与 NDK 崩溃直接经过原生 SDK，而 Dart 的事件过滤无法覆盖这些入口，因此当前停用原生崩溃采集。正式包继续默认关闭，开关文件无法读取时按关闭处理。

## 代价与边界

远端报告提供 Dart 异常的类型与代码位置，排查上下文仍需测试者主动提供本机诊断文件。原生崩溃和 ANR 缺少对应的远端事件，因此现有会话统计只用于观察开启上报用户的 Dart 异常，不能用来计算覆盖原生崩溃的总体崩溃率。

## 替代方案

对错误原文逐条增加脱敏规则可以保留更多调试信息，但模型服务、SQLite 插件和系统错误的格式会变化，应用无法预先枚举每种输出。需要恢复原生采集时，应先为原生入口实现同等字段约束，并用合成异常检查实际发送的报文。
