# ADR-0017 内测与公测期间表结构变化仍清空数据

## 状态

已采纳。补充 [ADR-0002](0002-本地数据不做迁移.md) 在内测之后的适用范围，原文保持当时的样子。

## 日期

2026-11-15

## 背景

ADR-0002 定的是开发期不写迁移，理由是当时只有可丢弃的测试数据。内测包 0.3.0 发出之后，2027.03 公测 100 人，用户开始写入真实学习记录；同一段时间里业务表主键要从自增整数改成 UUIDv7（[ADR-0018](0018-业务表主键改用UUIDv7.md)），这是一次必然的结构变化。04 第 5 节 D1 留过一个选项：0.3.0 之前完成主键改造，之后冻结表结构。冻结会把缺陷修复与新功能一起堵住，团队每周只有 8 小时，代价高于清空。

## 决定

1. 内测与公测期间（1.0.0 及之前的对外版本）表结构变化一律清空旧库并按当前结构重建，不写迁移函数、不保留兼容分支，与 ADR-0001、ADR-0002 一致。
2. 每次会清空数据的发版，在发版说明里写明数据处置，并在应用内首次进入时提示；内测用户另在内测群里提前通知。清空发生在打开旧版本数据库的那一刻，提示写在发版说明与版本说明里，不在启动流程里增加确认步骤。
3. 不设表结构冻结。结构改动照常按需要做，只要求 `main` 能构建、测试与文档同步。
4. 1.0.0 之后的结构改动是否引入迁移，另行决定。

## 代价与边界

- 内测与公测用户的真实记录会在清空时丢失，数据包与版本库备份只接受同一 schema 版本，清空那次发版之后旧包同样不可用。这条代价由 ADR-0002 的“只认当前版本”承担，不另做兼容。
- 清空提示依赖发版人执行，没有强制机制；漏一次提示不会阻塞发版，只影响用户预期。
- 03 第 4 节的留存指标会因清空中断样本，结题材料里要写明中断的日期与受影响人数。
- 结构变化频繁时用户会减少记录，这条代价无法用工程手段消除，只能靠把已知的结构改动集中在少数几次发版里。

## 替代方案

- 冻结表结构到 1.0.0，只允许阻断级缺陷改结构：新增字段与功能都要等，主键改造之后的缺陷修复也会被拖住；未采纳。
- 0.3.0 之后写迁移函数：与 ADR-0001 冲突，每次结构变化都要维护两套代码与两套测试；未采纳。
- 用导出再导入代替清空：数据包同样只认当前版本，改结构之后旧包也进不来，效果与清空相同，只多一步手工操作；未采纳。
